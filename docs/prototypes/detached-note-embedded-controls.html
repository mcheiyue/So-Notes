撕下便签 — 嵌入式控制方案原型

对比当前浮动工具栏方案与推荐的嵌入式右上角控制方案。核心原则：撕下便签的视觉主体应与画布便签保持一致， 控制操作作为便签表面的一部分自然浮现，而非外挂一个独立的工具栏。

方案对比 · 浅色模式
当前方案 浮动工具栏
产品规划 Q3
撕下便签的工具栏独立于便签表面之外，形成视觉断裂。用户需要将注意力从内容转移到外部控件上。

问题：工具栏与便签之间存在视觉空隙，看起来像一个外挂的小部件浮在便签上方， 破坏了便签作为独立信息单元的整体感。

推荐方案 嵌入式控制
悬停此便签查看控制浮现效果
产品规划 Q3
控制按钮嵌入便签右上角，悬停时从便签表面柔和浮现。便签保持完整的信息单元形态，不依赖外部工具栏。

优势：便签表面完整统一，控制操作像是便签的一部分。 用户视线无需跳离便签即可操作，认知负担更低。

方案对比 · 深色模式
当前方案 浮动工具栏
产品规划 Q3
深色模式下，浮动工具栏的磨砂玻璃背景与便签的有色亚克力表面形成两层独立材质，视觉层级冲突更明显。

问题：深色模式下两层材质叠加更突兀，工具栏的磨砂背景与便签的 tinted acrylic 表面互相干扰。

推荐方案 嵌入式控制
悬停此便签查看控制浮现效果
产品规划 Q3
控制按钮作为便签表面的一部分浮现，使用相同的深色材质语言。没有额外的材质层，视觉统一。

优势：控制区与便签表面融为一体，不引入新的视觉层级，整体更安静。

状态变体 · 置顶态 & 活跃态
置顶态 · 浅色
已置顶的便签
置顶时右上角 Pin 图标以蓝色常驻显示，hover 后 Pin 按钮继承蓝色高亮。

置顶态：Pin 指示器不依赖 hover，始终可见；hover 后控制组浮现，Pin 按钮保持蓝色。

活跃态 · 深色
正在编辑的便签
活跃态使用增强的 accent 边框光晕和更深层阴影，嵌入控制依然和谐。

活跃态：accent 边框光晕增强（alpha 0.1→0.14），阴影加深。控制按钮透明嵌入，不引入额外材质。

设计理据
  • 视觉一致性：撕下便签的本质是"同一张便签的另一个视口"，而非一个独立的 UI 控件。 当前方案的浮动工具栏破坏了这个隐喻——用户看到的是"便签 + 工具栏"两个对象，而非一张完整的便签。
  • 认知负担：嵌入式控制让用户的视线始终停留在便签表面。操作路径：看便签 → 视线自然移到右上角 → 操作。 当前方案：看便签 → 视线上移跳出便签 → 找工具栏按钮 → 操作 → 视线下移回便签。
  • 材质统一：深色模式下，当前工具栏的磨砂玻璃背景与便签的 tinted acrylic 表面是两层独立材质。 嵌入式方案的控制按钮直接浮于便签表面之上，不引入额外的视觉层级。
  • 安静的桌面工具：SoNotes 的设计语言是"安静"——便签是主角，UI 控件是配角。 嵌入式控制在默认状态下完全隐藏，只在用户主动悬停时柔和浮现，符合这个原则。
  • 不依赖外部工具栏：当前方案的工具栏位于便签上方，与便签之间有视觉空隙， 看起来像一个 macOS 风格的浮动小部件。嵌入式方案消除了这个空隙，让控制操作成为便签表面的一部分。
  • 实现路径：从 DetachedNoteOverlay.tsx 移除独立的 drag-handle 工具栏 div， 将三个按钮作为 NoteVisuals 的 children 嵌入，通过 position: absolute; top-right 定位， hover 时通过 opacity 实现浮现效果，按钮级 hover 提供轻量反馈。拖拽区域改为整个便签表面的顶部区域。
