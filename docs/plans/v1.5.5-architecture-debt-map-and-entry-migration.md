# SoNotes v1.5.5 实施计划：架构债地图与入口迁移

---

## 1. 背景

`v1.5.1` 到 `v1.5.4` 已经把备份信任链、WebDAV 协议边界和凭据安全逐步做硬。按照 `v1.5.1-v1.6.0` 总规划，进入定时备份、保留策略和活动日志之前，需要先处理 `v1.4.0` 留下的状态过渡层风险。

`v1.4.0` 已经确立了 Domain / Viewport / UI 拆分方向：

- Domain state：Note、Board、Trash、Image file reference、配置等可持久化领域状态。
- Viewport state：视口、画布尺寸、Shell 矩形、拖拽交互状态。
- UI state：ViewMode、选区、Dock、Spotlight、Quick Capture、撕下便签运行期状态等。

但当前项目仍处于过渡期：

- 旧 `useStore.ts` 仍是大量读写路径的主入口。
- `legacyDomainBridge` 将旧 `useStore` 的 Domain state 镜像到 `domainStore`。
- `uiStore` 与 `viewportStore` 已有双向同步桥，但不少 Controller / Component 仍直接写旧 `useStore`。
- `appController` 已经是跨层用例入口，但内部仍大量调用旧 `useStore.getState()`。

`v1.5.5` 不追求一次性删除旧 `useStore.ts`。本版本目标是把架构债变成可执行地图，并完成首批低风险入口迁移，让后续 `v1.5.6` 定时备份、`v1.5.7` 保留策略、`v1.5.8` 活动日志能建立在更清晰的 Module / Interface / Seam 上。

## 2. 当前代码基线

### 2.1 已存在的可复用 Module

- `src/store/domainStore.ts`
  - 已有 Domain state 与 Domain action：Board CRUD、Note CRUD、软删除 / 恢复 / 永久删除、颜色、折叠、复制、移动 / 复制到看板、批量 z-index 等。
  - 已有 `DomainPersistenceBridge`，用于把领域状态变更通知持久化层。
  - 尚未承接 Undo/Redo patch、完整历史栈和部分旧 store 编排语义。
- `src/store/uiStore.ts`
  - 已有 `viewMode`、`selectedIds`、`isDockVisible`、`isSpotlightOpen`、`isQuickCaptureOpen`、`isPinned`、`detachedNotes` 等 UI state。
  - 已有 `setViewMode`、`clearSelection`、`setDockVisible`、`setSpotlightOpen`、`setQuickCaptureOpen`、`setPinned` 等 UI action。
  - 通过双向同步桥与旧 `useStore` 保持一致。
- `src/store/viewportStore.ts`
  - 已有 `viewport`、`shellRect`、`canvas`、`interaction`、`stickyDrag` 等 Viewport state。
  - 已有 `setViewportPosition`、`setViewportSize`、`setShellRect`、`setPanMode`、`setStickyDrag` 等 Viewport action。
  - 通过双向同步桥与旧 `useStore` 保持一致。
- `src/controllers/appController.ts`
  - 已是快捷键、菜单、Spotlight、Quick Capture、撕下便签、创建便签、定位便签等跨层用例入口。
  - 但 Interface 目前偏浅，许多方法只是旧 `useStore.getState()` 的透传。

### 2.2 旧 `useStore` 依赖分布

当前生产代码中仍存在旧 `useStore` 依赖，第一版依赖地图应至少覆盖以下类别：

| 类别 | 代表文件 | 当前性质 | v1.5.5 处理策略 |
| --- | --- | --- | --- |
| Controller 旧 store 读写 | `src/controllers/appController.ts` | UI / Viewport / Domain / 跨层混合 | 首批迁移 UI-only 与 Viewport-only 入口 |
| Canvas / engine 旧 store 读写 | `src/components/Canvas.tsx`、`src/canvas/CanvasEngine.ts`、`src/components/NoteCard.tsx` | 高频交互、拖拽落位、选区、创建便签 | 本版本只建图，不迁移拖拽主路径 |
| 组件直接执行 Domain 写入 | `src/components/SelectionActionBar.tsx`、`src/components/TrashGrid.tsx`、`src/components/ShortcutsManager.tsx` | 删除、恢复、合并、拆分、撤销 / 重做等领域操作 | 建图并排序，暂不迁移高风险写路径 |
| 组件只读旧 store 订阅 | `src/components/BoardDock.tsx`、`src/components/DiagnosticsPanel.tsx`、`src/components/SmartPasteSplitBubble.tsx`、`src/components/QuickCaptureOverlay.tsx` | UI 展示、诊断、备份面板、局部状态读取 | 只迁移低风险 UI-only 读路径 |
| 服务旧 store 读取 | `src/services/detachedNoteSnapshotSync.ts` | 撕下窗口快照、主题、Note 内容同步 | 建图，不纳入首批迁移 |
| 启动 / 持久化旧 store 入口 | `src/main.tsx`、`src/components/PersistenceController.tsx` | 初始化、保存、WAL / disk 兼容 | 建图，不在 v1.5.5 改写 |
| 测试旧 store 初始化 | `*.test.ts(x)` | 夹具构造、断言旧镜像状态 | 本版本允许保留，但新增迁移测试应断言新 Store 与旧镜像一致 |

### 2.3 首批可迁移入口

适合第一批迁移的入口必须满足：

- 不改变用户可见行为。
- 不改变持久化格式。
- 不触碰 Undo/Redo patch 应用。
- 不触碰拖拽落位与高频 Canvas 更新。
- 新 Store 已有等价 action，且双向同步桥可以保护旧订阅路径。

建议首批迁移：

- `appController.showBoardDock()`：旧 `setDockVisible(true)` -> `useUIStore.getState().setDockVisible(true)`。
- `appController.openSpotlight()` / `closeSpotlight()` / `toggleSpotlight()`：旧 `isSpotlightOpen` / `setSpotlightOpen` -> `useUIStore`。
- `appController.setPinned()`：旧 `setPinned` -> `useUIStore`。
- `appController.setViewMode()` / `toggleViewMode()` / `enterTrashMode()` / `enterBoardMode()`：旧 `viewMode` / `setViewMode` / `clearSelection` -> `useUIStore`。
- `appController.openQuickCapture()`：旧 `setQuickCaptureOpen(true)` -> `useUIStore`，并让 `runOnBoardView()` 读取 `useUIStore.viewMode`。
- `appController.resetViewport()`：旧 `setViewportPosition(0, 0)` -> `useViewportStore`。
- `appController.syncShellViewport()`：旧 `viewport` / `shellRect` / `setViewportSize` / `setShellRect` -> `useViewportStore`。
- `useCanvasGlobalListeners()` 中 Space 处理的 Spotlight 只读判断：旧 `useStore.getState().isSpotlightOpen` -> `useUIStore.getState().isSpotlightOpen`。

### 2.4 暂不迁移入口

以下路径虽然也依赖旧 `useStore`，但不应进入首批：

- `CanvasEngine.moveSelectedNotes()` 与拖拽落位。
- `Canvas.tsx` 的框选、创建便签、图片批量创建、ContextMenu 写入。
- `NoteCard.tsx` 的移动快照、拖拽、折叠、编辑提交。
- `ShortcutsManager.tsx` 的 `undoDomainChange()` / `redoDomainChange()`。
- `SelectionActionBar.tsx` 的合并、拆分、删除、复制、批量颜色、排列。
- `TrashGrid.tsx` 的恢复、永久删除、清空废纸篓。
- `BoardDock.tsx` 的备份恢复后状态替换、WAL 清理、WebDAV 操作。
- `detachedNoteSnapshotSync.ts` 与撕下窗口内容同步。
- `locateAndSelectNote()` / `locateDetachedNote()` 这类同时跨 Domain、Viewport、UI、DOM readiness 的复合编排。

这些入口需要依赖地图和后续版本排序，不应在 `v1.5.5` 为了减少引用数量而冒进。

## 3. 版本目标

### 3.1 建立旧 Store 依赖地图

新增依赖地图文档，建议路径：

```text
docs/plans/v1.5.5-use-store-dependency-map.md
```

地图需要记录：

- 文件路径。
- 依赖类型：`read`、`write`、`subscribe`、`test_fixture`、`bridge`。
- 状态分类：`Domain`、`Viewport`、`UI`、`Cross-layer`、`Persistence`、`Test`。
- 当前 Interface。
- 推荐目标 Module。
- 风险等级：`low`、`medium`、`high`。
- 迁移批次：`v1.5.5-first`、`later`、`blocked`。
- 备注：是否涉及 Undo/Redo、拖拽高频路径、备份恢复、撕下窗口、持久化格式。

依赖地图不是静态说明书，而是后续删除旧 `useStore` 的执行索引。

### 3.2 深化 `appController` Interface

`appController` 应继续作为跨层用例 Module，但需要降低对旧 `useStore` 的透传依赖。

本版本先把 UI-only 与 Viewport-only 用例改为：

- UI state 只通过 `useUIStore` action 写入。
- Viewport state 只通过 `useViewportStore` action 写入。
- Domain 写入暂时保留旧 `useStore`，但在依赖地图里标记目标 Module。
- 跨层编排继续留在 `appController`，不下沉到 Store。

这会让 `appController` 的 Seam 更清楚：调用方只知道“打开 Spotlight / 重置视口 / 切换 ViewMode”，不需要知道旧 store 是否还存在。

### 3.3 保持过渡桥稳定

本版本不删除：

- `legacyDomainBridge`
- `uiStore` 双向同步桥
- `viewportStore` 双向同步桥
- 旧 `useStore.ts`

迁移后的新 Store 写入仍需要通过现有同步桥反向同步到旧 `useStore`，保证未迁移组件和既有测试继续工作。

### 3.4 保护渲染性能边界

架构迁移不得破坏细粒度订阅：

- MiniMap 不应订阅粗粒度根状态。
- Canvas 不应因为 UI / Viewport 小变动触发全部 Note 重渲染。
- NoteCard 的 memo / selector 边界不应被替换成大对象订阅。
- Viewport 高频更新不得变成 Domain state 全量提交。

本版本只迁移低频 Controller 入口和一个低风险只读 UI 路径，避免触碰拖拽主链路。

---

## 4. 非目标

本版本不做：

- 不一次性删除旧 `useStore.ts`。
- 不删除 `legacyDomainBridge`。
- 不重写 Zustand store 架构。
- 不替换 Zustand。
- 不引入 SQLite / libSQL。
- 不改变备份格式、WebDAV 格式或本地持久化格式。
- 不实现定时备份、保留策略、活动日志。
- 不迁移 Undo/Redo patch 应用。
- 不迁移拖拽落位、hover panning、高频 Canvas 引擎路径。
- 不迁移备份恢复后的状态替换路径。
- 不迁移撕下窗口快照同步。
- 不改变用户可见行为。

## 5. 技术设计

### 5.1 依赖地图生成方式

第一版可以用 `rg` 形成基线，再人工分类。下面命令不依赖 PowerShell 专有语法，在 PowerShell / Git Bash / bash 下均可运行：

```powershell
rg -n "useStore|getState\(|subscribe\(" src --glob "!**/*.test.*"
rg -n "useStore|getState\(|subscribe\(" src --glob "**/*.test.*"
```

依赖地图建议使用表格：

```md
| Module | File | Dependency | State Class | Current Interface | Target Module | Risk | Batch | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| appController | src/controllers/appController.ts | write | UI | useStore.getState().setSpotlightOpen | uiStore | low | v1.5.5-first | 双向桥保护旧观察者 |
```

其中 `Module` 用代码承担的职责命名，不只写文件名：

- `appController`
- `CanvasEngine`
- `Canvas`
- `NoteCard`
- `SelectionActionBar`
- `TrashGrid`
- `PersistenceController`
- `detachedNoteSnapshotSync`
- `legacyDomainBridge`
- `uiStore`
- `viewportStore`
- `BoardDock`

### 5.2 `appController` UI 入口迁移

建议在 `appController.ts` 中引入清晰的内部读取函数，避免每个方法散落 `useUIStore.getState()`：

```ts
const getUIState = () => useUIStore.getState();
const getViewportState = () => useViewportStore.getState();
```

如果引入 helper，本次新增或迁移过的 UI / Viewport 调用点应统一使用 helper。`detachNote`、`showAllDetachedNotes` 等现有方法已经直接使用 `useUIStore.getState()`；Commit 4 可以一并做机械替换来统一同文件风格，但不应借此扩大迁移范围或改变撕下窗口行为。

低风险 UI 用例迁移规则：

- `setViewMode(mode)` 使用 `getUIState().setViewMode(mode)`。
- `toggleViewMode()` 使用 `getUIState().viewMode` 判断，再调用 `setViewMode()`。
- `enterTrashMode()` / `enterBoardMode()` 调用 `getUIState().setViewMode()`。
- 不需要额外 `clearSelection()`，因为 `uiStore.setViewMode()` 已清空 `selectedIds`。
- `showBoardDock()`、`openSpotlight()`、`closeSpotlight()`、`setPinned()` 直接调用对应 UI action。
- `toggleSpotlight()` 读取 `getUIState().isSpotlightOpen` 后写回。
- `openQuickCapture()` 继续走 `runOnBoardView()`，但 `runOnBoardView()` 读取 `getUIState().viewMode`。

迁移后旧 `useStore` 中对应字段仍应通过 `uiStore` 反向同步保持一致。

### 5.3 `appController` Viewport 入口迁移

低风险 Viewport 用例迁移规则：

- `resetViewport()` 调用 `getViewportState().setViewportPosition(0, 0)`。
- `syncShellViewport(rect)` 读取 `getViewportState().viewport` 与 `getViewportState().shellRect`。
- 尺寸变化时调用 `getViewportState().setViewportSize(nextWidth, nextHeight)`。
- Shell 矩形变化时调用 `getViewportState().setShellRect(nextRect)`。

注意：

- `syncShellViewport()` 不应额外写 Domain state。
- 不应引入新的全局 resize 订阅。
- 不应扩大为自动保存 Board viewport。

过渡期允许 `appController` 内存在“Viewport 写入走 `viewportStore`、复合用例读取仍走旧 `useStore`”的混用状态。`createNoteAtViewportOrigin()`、`smartPasteFromText()`、`detachNote()`、`locateAndSelectNote()`、`locateDetachedNote()` 仍会通过旧 `useStore.getState().viewport` 读取视口，这是 v1.5.5 的已知状态；双向同步桥会保持行为正确。后续维护者不应为了“统一读写来源”顺手迁移这些复合编排，除非同时补齐 Domain / Viewport / UI / DOM readiness 的行为测试。

### 5.4 一个非 Controller 只读迁移

`src/hooks/useCanvasGlobalListeners.ts` 当前仅为了 Space 键逻辑读取 `useStore.getState().isSpotlightOpen`。

该读取属于 UI-only 低风险路径，建议迁移为：

```ts
const isSpotlightOpen = useUIStore.getState().isSpotlightOpen;
```

这个迁移有两个价值：

- 证明依赖地图不只停留在 `appController`。
- 在不触碰 Canvas 拖拽落位的情况下，减少一个高频交互 hook 对旧 store 的直接依赖。

### 5.5 测试策略

迁移测试应证明三件事：

- 新 Store 被写入。
- 旧 `useStore` 镜像仍保持一致。
- 用户可见行为不变。

这些测试是回归护栏，不要求在迁移前呈现红灯。由于 UI / Viewport 双向同步桥已经存在，迁移前通过旧 `useStore` 写入也可能同步到新 Store，因此“新旧 Store 一致”的断言很可能迁移前就是绿色。除非明确接受实现耦合，否则不建议用 spy 断言 `appController` 是否调用过 `useStore.getState()`。

建议覆盖：

- `appController.openSpotlight()` / `closeSpotlight()` / `toggleSpotlight()` 同步更新 `useUIStore` 与旧 `useStore`。
- `appController.setViewMode()` / `toggleViewMode()` / `enterTrashMode()` / `enterBoardMode()` 更新 `useUIStore.viewMode`，并清空 `useUIStore.selectedIds` 与旧 `useStore.selectedIds`。
- `appController.showBoardDock()` 更新 `useUIStore.isDockVisible` 与旧 `useStore.isDockVisible`。
- `appController.setPinned()` 更新 `useUIStore.isPinned` 与旧 `useStore.isPinned`。
- `appController.resetViewport()` 更新 `useViewportStore.viewport` 与旧 `useStore.viewport`。
- `appController.syncShellViewport()` 更新 `useViewportStore.viewport.w/h`、`useViewportStore.shellRect` 与旧 `useStore` 镜像。
- `useCanvasGlobalListeners()` Space 键逻辑在 Spotlight 打开时仍不切换 Pan mode。

推荐回归命令：

PowerShell：

```powershell
.\node_modules\.bin\vitest.cmd run --reporter=dot src/controllers/appController.test.ts src/components/Canvas.test.tsx src/components/MiniMap.test.tsx
```

Git Bash / bash：

```bash
./node_modules/.bin/vitest run --reporter=dot src/controllers/appController.test.ts src/components/Canvas.test.tsx src/components/MiniMap.test.tsx
```

如果时间有限，最低验收可先跑：

PowerShell：

```powershell

```

Git Bash / bash：

删除条件建议保持四条：

- 旧 `useStore` 不再作为 Domain 写入主路径。
- Domain state 的订阅、持久化和测试不再依赖旧 store 镜像。
- Viewport / UI 迁移项已从旧 store 归位。
- Canvas、Undo/Redo、备份恢复、撕下窗口等关键交互已有迁移前后行为测试。

验收：

- 后续版本能从依赖地图继续推进，而不是重新考古。
- 文档明确哪些路径不能在 `v1.5.5` 强拆。

## 7. 风险与防护

### 7.1 双向同步桥循环风险

风险：

- 新 Store 写入后反向同步旧 `useStore`。
- 旧 `useStore` 订阅又可能触发新 Store 同步。

防护：

- 继续使用现有 `hasUIStoreFieldChanged` / `hasViewportStoreFieldChanged` 与引用比较。
- 本版本不改同步桥机制。
- 测试同时断言新 Store 与旧 Store 镜像，避免静默断链。

### 7.2 ViewMode 清空选区语义差异

风险：

- 旧 `appController` 先 `clearSelection()` 再 `setViewMode()`。
- `uiStore.setViewMode()` 内部已经清空 `selectedIds`。

防护：

- 迁移后不要重复手写 `clearSelection()`，避免额外状态提交。
- 测试覆盖 `toggleViewMode()`、`enterTrashMode()`、`enterBoardMode()` 清空选区。

### 7.3 测试夹具仍读旧 Store

风险：

- 大量现有测试通过旧 `useStore` 初始化和断言。
- 如果新 Store 初始状态未同步，测试可能出现顺序相关问题。

防护：

- v1.5.5 不要求测试夹具全部迁移。
- 新增测试只要求关键入口同时验证新 Store 与旧镜像。
- 后续版本再单独处理测试初始化 Module。

### 7.4 过早迁移 Domain 写入

风险：

- 直接把删除、恢复、合并、拆分、撤销 / 重做迁到 `domainStore`，可能绕开历史栈、持久化、布局快照或 UI 联动。

防护：

- `v1.5.5` 不迁移高风险 Domain 写入。
- 依赖地图先记录目标 Module 与阻塞条件。

## 8. 验收标准

`v1.5.5` 完成时应满足：

- 新增 `v1.5.5-use-store-dependency-map.md`，并覆盖生产代码与测试代码中的旧 `useStore` 依赖。
- 至少一类跨层入口不再直接依赖旧 `useStore.getState()`；本版本建议为 `appController` 的 UI-only 与 Viewport-only 入口。
- `appController` 中首批迁移入口改为通过 `useUIStore` / `useViewportStore` action 写入。
- `useCanvasGlobalListeners` 中 Spotlight 只读判断不再依赖旧 `useStore`。
- 迁移测试证明新 Store 与旧 `useStore` 镜像一致。
- `legacyDomainBridge` 仍保留，且删除条件已写入依赖地图。
- MiniMap / Canvas / NoteCard 的细粒度订阅边界未被改写。
- 没有用户可见行为变化。
- 推荐回归测试通过。

## 9. 版本完成后的下一步

`v1.5.5` 完成后，建议按总规划进入：

- `v1.5.6`：定时备份与最小活动记录。
- `v1.5.7`：备份保留策略与远端清理。
- `v1.5.8`：完整活动日志与可观测性。

但有一个顺序约束：如果 `v1.5.5` 发现备份恢复、持久化初始化或旧 store 桥接存在阻断性问题，应先补一个小修版本修掉，再进入定时备份。定时备份属于后台自动写入能力，不应建立在未分类的状态写入路径上。
