# SoNotes v1.5.4 实施计划：WebDAV 凭据安全

---

## 1. 背景

`v1.5.3` 已经把 WebDAV 协议边界、请求目标、错误分类、mock / fixture 测试资产补齐。到 `v1.5.4`，应按总规划推进 **WebDAV 凭据安全**，把“记住密码”从不可用占位推进到系统密钥链闭环。

当前代码已有安全基础：

- Rust 侧拒绝 `remember_password=true`，不会把密码 / 应用令牌写入 `webdav-config.json`。
- `webdav-config.json` 当前只保存 WebDAV 地址、用户名、远端目录和 `password_saved`。
- `prepare_config_save()` 永远写入 `password_saved: false`。
- `WebDavConfig` / `WebDavConfigSaveRequest` Debug 输出已经脱敏。

当前缺口：

- 前端仍显示“记住密码”复选框，勾选后只会保存失败。
- 保存配置时前端会把 password 一并传给 `webdav_save_config`，虽然 Rust 不持久化，但当前没有安全存储闭环。
- `passwordSaved` 字段尚无真实密钥链语义。
- 清除配置只删除本地配置文件，没有系统凭据删除逻辑。
- 远端操作缺少前端 password 时，不能从安全存储读取 secret。

`v1.5.4` 的主路径明确为：**接入系统密钥链**。会话凭据模式只作为系统密钥链不可用、读取失败或回滚时的降级路径，不作为本版本主目标。

## 2. 当前代码基线

### 2.1 Rust 侧

- `src-tauri/src/webdav.rs`
  - `WebDavConfig.password` 只随操作请求进入 Rust，不写入配置文件。
  - `WebDavConfigSaveRequest.remember_password` 当前为 `true` 时直接拒绝。
  - `WebDavConfigSaveRequest.password` 仍存在，但 `prepare_config_save()` 不持久化。
  - `WebDavConfigFile` 当前保存 `server_url`、`username`、`remote_dir`、`password_saved`。
  - `webdav_load_config()` 当前会把配置文件中的 `password_saved` 原样返回。
  - `build_webdav_request_target()` 会把 `password` 放入 `WebDavRequestTarget`，但不负责读取系统凭据。

### 2.2 前端侧

- `src/components/BoardDock.tsx`
  - `webdavDraft` 包含 `serverUrl`、`username`、`password`、`remoteDir`、`rememberPassword`。
  - 加载配置时会清空 `password`。
  - 保存配置时会传入 `rememberPassword` 和 `password`。
  - UI 显示“记住密码”复选框。
  - 测试连接、刷新列表、创建远端备份、删除、远端恢复都复用 `buildWebdavConfig()`。

### 2.3 依赖侧

- `src-tauri/Cargo.toml` 当前没有跨平台 keyring / credential crate。
- Windows 平台已有 `windows` crate，但当前 feature 只覆盖窗口相关能力。
- `v1.5.4` 建议优先采用成熟的跨平台 `keyring` crate；如实现中发现平台阻塞，再降级到会话模式并记录原因。

## 3. 版本决策

### 3.1 选择系统密钥链作为主线

本计划不再保留 A/B 双轨实施。`v1.5.4` 直接选择系统密钥链路径：

- 使用成熟 keyring / credential 方案保存 WebDAV secret。
- `webdav-config.json` 只保存非敏感字段和密钥链引用。
- `passwordSaved: true` 表示“存在系统凭据引用”，不表示 secret 会回填到前端。
- 远端操作优先使用本次输入 password；如果为空且配置有 saved credential，则从系统密钥链读取。
- 密钥链读取失败时提示用户重新输入，并允许本次会话 password 继续操作。

### 3.2 会话模式只作为降级

以下情况允许降级到会话模式：

- 当前平台没有可用密钥链服务。
- Linux headless / CI 环境没有 Secret Service。
- keyring 依赖或打包验证出现阻塞。
- 用户选择不记住密码。
- 密钥链读取失败，需要用户重新输入 password。

降级规则：

- password / token 只保留在当前设置面板会话。
- 不写入普通配置文件。
- 远端操作缺少可用 secret 时本地拦截，不发起 WebDAV 请求。

### 3.3 安全底线

无论密钥链是否可用，都必须满足：

- password / token 不写入 `webdav-config.json`。
- 不保存 Basic Auth header。
- 不保存带 userinfo 的 WebDAV URL。
- 不把凭据写入 zip 备份包。
- Debug、错误、前端 feedback、活动记录不包含 secret。
- 清除配置后，本地配置引用必须失效。
- 如果密钥链删除失败，必须提示用户可能需要手动检查系统凭据管理器。

## 4. 目标

### 4.1 Credential Store 抽象

Rust 侧新增 credential store 边界，避免业务逻辑直接依赖真实系统密钥链：

```rust
trait WebDavCredentialStore {
    fn save(&self, key: &WebDavCredentialKey, secret: &str) -> Result<(), WebDavCredentialError>;
    fn load(&self, key: &WebDavCredentialKey) -> Result<String, WebDavCredentialError>;
    fn delete(&self, key: &WebDavCredentialKey) -> Result<(), WebDavCredentialError>;
}
```

实现：

- `SystemWebDavCredentialStore`：生产环境使用 keyring / 系统密钥链。
- `MemoryWebDavCredentialStore`：测试环境使用内存实现。

硬约束：

- `cargo test webdav` 不依赖真实系统密钥链。
- Linux headless / CI 没有 Secret Service 时，单元测试不失败。
- 真实 keyring 测试只能作为手动 / gated integration 测试，不进入默认回归命令。

### 4.2 Credential Key 与孤儿 secret 防护

密钥链 account key 必须稳定且不包含 secret：

```text
service: SoNotes.WebDAV
account: sha256("v1\n" + normalized_server_url + "\n" + username + "\n" + normalized_remote_dir)
```

配置文件新增 `credential_key`：

```json
{
  "server_url": "https://example.com/dav",
  "username": "user1",
  "remote_dir": "SoNotes_Backups/",
  "password_saved": true,
  "credential_key": "sha256..."
}
```

保存新 secret 前必须读取旧配置：

- 如果旧配置存在 `credential_key`，且与新 key 不同，先删除旧 secret。
- 如果 `remember_password=true` 且旧 secret 删除失败，保存新配置前应中止并提示用户，避免制造孤儿 secret。
- 如果 `remember_password=false` 且旧 secret 删除失败，仍写入 `password_saved: false` / `credential_key: None`，并返回 warning，满足用户“不要再记住密码”的意图。
- 如果新 secret 已写入但配置文件写入失败，应 best-effort 删除新 secret。
- 清除配置必须使用配置文件中记录的旧 `credential_key` 删除 secret，而不是重新按当前表单计算。

### 4.3 URL 与配置安全

必须显式测试：

- `normalize_webdav_url()` 当前已经拒绝 userinfo；`v1.5.4` 必须保留该行为。
- `https://user:pass@example.com/dav` 被拒绝。
- 含 userinfo 的 URL 不会被保存到配置文件。
- `credential_key` 不包含 password、token、username:password、Authorization header。
- `webdav-config.json` 不包含 `password` 字段。

### 4.4 `passwordSaved` 语义

`passwordSaved: true` 表示“配置中存在系统凭据引用”，但不保证打开设置面板那一刻已经成功读取 secret。

该布尔值只由 `webdav_load_config()` 计算并返回：`config.password_saved && config.credential_key.is_some()`。`credential_key` 是 Rust 内部删除依据，不暴露给前端。

前端文案应表达为：

- “已保存到系统凭据管理器”
- “密码不会在此显示”
- “如果系统凭据不可用，操作时会提示重新输入”

不要表达为：

- “密码已加载”
- “密码可用”
- “无需重新输入”

密钥链读取失败只能在实际操作或显式测试连接时发现，发现后提示用户重新输入。

## 5. 非目标

本版本不做：

- 不把 password / token 写入 `webdav-config.json`。
- 不做 OAuth。
- 不做多 WebDAV 账户。
- 不做主密码、加密配置文件或自研 secret vault。
- 不新增定时备份。
- 不实现 WebDAV 同步、多端合并或冲突解决。
- 不改变 zip 备份格式。
- 不新增远端服务商适配层。
- 不把密钥链错误上传或遥测。

## 6. 技术设计

### 6.1 Rust 类型

建议新增：

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
struct WebDavConfigFile {
    server_url: String,
    username: String,
    remote_dir: String,
    password_saved: bool,
    credential_key: Option<String>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
struct WebDavCredentialKey {
    service: String,
    account: String,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum WebDavCredentialErrorKind {
    Unavailable,
    SaveFailed,
    LoadFailed,
    DeleteFailed,
    MissingSecret,
}
```

建议扩展配置保存 / 清除结果：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct WebDavConfigSaveResult {
    pub success: bool,
    pub warning: Option<String>,
    pub error: Option<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct WebDavConfigClearResult {
    pub success: bool,
    pub secret_cleanup_warning: Option<String>,
    pub error: Option<String>,
}
```

`warning` / `secret_cleanup_warning` 只用于表达“本地配置已按用户意图更新，但系统凭据删除需要手动确认”。这类情况 `success` 保持 `true`，避免前端误判为配置清除失败而保留旧表单状态。

错误对象不得保存 secret。用户文案由独立函数生成。

### 6.2 保存配置流程

`webdav_save_config()` 流程：

1. 读取旧配置文件，记录旧 `credential_key`。
2. 规范化 server URL 和 remote dir。
3. 拒绝含 userinfo / query / fragment 的 URL，沿用 `normalize_webdav_url()`。
4. 根据规范化后的 URL、username、remote dir 计算新 `credential_key`。
5. 如果 `remember_password=true`：
   - 要求 request.password 非空。
   - 如果旧 key 存在且不同，先删除旧 secret；删除失败则中止。
   - 保存新 secret 到系统密钥链。
   - 原子写入配置文件，`password_saved: true`，`credential_key: Some(new_key)`。
   - 如果配置写入失败，best-effort 删除新 secret。
6. 如果 `remember_password=false`：
   - 如果旧 key 存在，尝试删除旧 secret。
   - 原子写入配置文件，`password_saved: false`，`credential_key: None`。
   - 如果旧 secret 删除失败，仍写入新配置，并通过 `warning` 提示用户可能需要手动清理系统凭据管理器。

### 6.3 加载配置流程

`webdav_load_config()`：

- 返回 server URL、username、remote dir。
- 返回 `passwordSaved: config.password_saved && config.credential_key.is_some()`。
- 永远不返回 secret。
- 永远不向前端暴露 `credential_key`。
- 如果旧配置 `password_saved=true` 但 `credential_key` 缺失，应视为 `passwordSaved: false`。
- 不在 load 阶段读取系统密钥链，避免打开设置面板时触发系统弹窗或 headless 失败。

### 6.4 远端操作凭据解析

新增内部解析：

```rust
fn resolve_webdav_operation_secret(
    config: &WebDavConfig,
    saved_config: Option<&WebDavConfigFile>,
    store: &dyn WebDavCredentialStore,
) -> Result<String, WebDavCredentialError>
```

规则：

- 如果 `config.password` 非空，优先使用本次输入。
- 如果 `config.password` 为空，且 saved config 有 `credential_key`，尝试从 store 读取 secret。
- 读取成功后只注入当前请求目标，不写回前端。
- 读取失败返回 `LoadFailed`，提示用户重新输入。
- 如果无本次输入也无 saved credential，返回 `MissingSecret`，不发起网络请求。

覆盖命令：

- `webdav_test_connection`
- `webdav_list_backups`
- `webdav_create_remote_backup`
- `webdav_download_backup`
- `webdav_delete_backup`

### 6.5 清除配置流程

`webdav_clear_config()`：

1. 读取旧配置中的 `credential_key`。
2. 删除配置文件或确认配置文件不存在。
3. 如果旧 key 存在，尝试删除 keychain secret。
4. 如果 secret 删除失败：
   - 本地配置引用仍然清除。
   - 返回 `success: true`。
   - 返回 `secret_cleanup_warning: Some(...)`，说明“配置已清除，但系统凭据可能需要手动删除”。
5. 前端清空 password、远端列表和 saved credential 状态。

### 6.6 前端体验

保存配置：

- “记住密码”保留并真正可用。
- 勾选时要求 password 非空。
- 成功后显示“配置已保存，密码已保存到系统凭据管理器。”
- 不勾选时允许保存非敏感配置，成功后显示“配置已保存，密码仅用于本次会话。”

加载配置：

- `passwordSaved=true` 时显示“已保存到系统凭据管理器，密码不会在此显示。”
- 不回填 password。
- 不声称系统凭据当前一定可读取。

操作：

- 如果 password 输入框为空但 `passwordSaved=true`，允许操作，由 Rust 读取 keychain。
- 如果 Rust 返回读取失败，提示“系统凭据读取失败，请重新输入密码或应用令牌。”
- 如果 password 为空且 `passwordSaved=false`，前端本地提示输入本次会话 password，不调用网络服务。

### 6.7 测试隔离

Rust 默认单元测试：

- 使用 `MemoryWebDavCredentialStore`。
- 不访问真实系统密钥链。
- 不依赖 Secret Service、Windows Credential Manager、macOS Keychain。

真实 keyring 集成测试：

- 可放在 `#[ignore]` 测试或单独 feature 下。
- 不进入默认 `cargo test webdav`。
- 仅用于手动验证打包环境。

测试 secret 统一常量：

```rust
const TEST_SECRET: &str = "super-secret-token";
```

所有“不应泄漏 secret”的断言引用该常量，避免散落。

## 8. 验收清单

`v1.5.4` 完成时应满足：

- “记住密码”使用系统密钥链或等价安全存储。
- password / token 不出现在 `webdav-config.json`。
- password / token 不出现在 Debug、错误、feedback 或诊断记录中。
- 凭据不写入 zip 备份包。
- 默认 Rust 测试使用内存 credential store，不依赖真实系统密钥链。
- `passwordSaved: true` 表示存在系统凭据引用，但 load 不返回 secret。
- load result 不向前端暴露 `credential_key`。
- 含 userinfo 的 WebDAV URL 被拒绝且不会保存。
- 修改 server URL / username / remote dir 时旧 credential key 被清理或保存被中止。
- `remember_password=false` 保存能写入 `password_saved: false` / `credential_key: None`，并在 secret 删除失败时返回 warning。
- 清除配置使用旧配置中的 `credential_key` 删除 secret。
- keychain 读取失败提示重新输入。
- keychain 删除失败时 clear result 为 `success: true` 且带 `secret_cleanup_warning`，前端仍清空本地状态。
- 缺少可用凭据时不发起 WebDAV 网络请求。
- 创建远端备份缺凭据时不调用 `flushNow()`。
- `v1.5.3` 的 WebDAV 错误分类、mock / fixture 和恢复前验证流程不回退。

## 9. 风险与回滚

### 9.1 风险：keyring 跨平台复杂度超出小版本

控制方式：

- Credential store trait 先落地。
- 默认测试只走内存实现。
- 真实 keyring 测试 gated / ignored。
- 如果生产 keyring 实现不稳定，回滚到会话模式，但保留“不明文持久化”的安全底线。

### 9.2 风险：孤儿 secret

控制方式：

- 配置文件保存 `credential_key`。
- 保存新 secret 前按旧配置删除旧 key。
- 清除配置按旧配置删除 secret。
- 写配置失败时 best-effort 删除新 secret。

### 9.3 风险：用户误解 password 已回填

控制方式：

- load 不返回 secret。
- 前端只显示“已保存到系统凭据管理器”。
- 文案说明“如果系统凭据不可用，操作时会提示重新输入”。

### 9.4 回滚策略

如果 keychain 实现必须回滚：

- 回滚 `SystemWebDavCredentialStore` 接入。
- 保留 credential store trait 和内存测试。
- 降级为会话凭据模式。

不得回滚到：

- password 写入 JSON。
- Basic Auth header 写入配置。
- 带凭据 URL 写入配置。
- 前端“记住密码”勾选后实际明文保存。
