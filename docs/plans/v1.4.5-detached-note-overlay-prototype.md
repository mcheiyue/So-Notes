# SoNotes v1.4.5 实施计划：撕下便签主窗口内浮层原型

---

## 1. 背景

`v1.4.4` 已经完成了通用 Undo/Redo 的批量操作与复杂操作迁移，建立了复合 `DomainPatch`、软删除 / 废纸篓还原 / 归拢 / 拆分 / 合并的可逆历史记录，以及编辑尺寸偏好能力。当前项目的基础交互框架、历史机制和状态边界都已经稳定。

根据后续路线图（阶段三：撕下便签 / 只读镜像视图），SoNotes 需要允许用户将某个 **Note（便签）** 从主画布"撕下"为一个独立的只读镜像视图，用于临时悬浮查看。原始便签仍属于当前 **Board（看板）**，画布中的便签仍然是唯一可编辑来源。该能力强化桌面便签的空间感，但不改变 **Domain state（领域状态）** 的事实来源。

本版本定位为主窗口内浮层原型，先验证交互语义、按钮行为和渲染复用，不引入 Tauri 多窗口复杂度。OS 级 always-on-top 独立窗口能力推迟到 `v1.4.6`。

---

## 2. 目标

### 2.1 建立只读分离视图组件

- 抽取便签的纯展示部分，包括：便签背景、阴影、边框、颜色计算、标题与正文只读展示、折叠态展示、尺寸与视觉度量。
- 新增 `DetachedNoteOverlay` 浮层组件，使用抽取的纯展示能力渲染便签的只读镜像。
- 浮层组件不复用完整 `NoteCard`，避免带入拖拽、编辑、选择、右键菜单、DOM 注册等画布职责。

### 2.2 实现主窗口内浮层交互

- 在主窗口画布上方叠加浮层容器，支持同时显示多个撕下视图。
- 浮层默认覆盖在画布之上，不遮挡主窗口其他 UI 元素。
- 用户可通过画布便签右键菜单的"撕下便签"操作触发浮层。
- 同一 **Note** 不得重复打开多个撕下视图；已打开时应聚焦现有浮层而非创建新实例。

### 2.3 三个核心按钮行为

| 按钮 | 行为 | 状态影响 |
|---|---|---|
| 定位到画布所在 | 显示主窗口，切回 Note 所在 Board，定位、选中并高亮原便签 | 只影响 **Viewport state / UI state** |
| 置顶 | 切换浮层的 z-index 层级优先级，使其保持在其他浮层之上 | 只影响浮层运行态的 **UI state** |
| 贴回画布 | 关闭撕下视图，回到原始画布便签 | 不修改 **Domain state** |

**置顶决策**：v1.4.5 的"置顶"行为仅表示主窗口浮层的 z-index 层级优先级，不涉及操作系统级 always-on-top 窗口置顶。OS 级置顶推迟到 `v1.4.6` 独立窗口版本。

### 2.4 同步展示最新内容

- 用户在画布中修改 **Note** 后，撕下视图同步映射最新内容。
- 同步范围仅限当前撕下的那张 **Note**，不订阅或广播其他便签状态。
- 同步基于运行态 **Domain state** 变更，不依赖全局事件广播。

### 2.5 定位到画布所在

- 点击"定位到画布所在"后，如果当前不在 **BOARD（看板）** 视图，切换到 **BOARD** 视图。
- 切换到便签所属 **Board**，平移 **Viewport state** 使便签居中，高亮并选中便签。
- 高亮作为临时 **UI state** 反馈，不持久化。

**渲染时序约束**：跨 Board 切换时，底层 DOM 树会经历卸载与挂载。`appController.locateDetachedNote` 必须是一个感知 React 渲染周期的异步操作——切换 **ViewMode** 或 **Board** 后，必须等待目标 Board 画布和 Note DOM 注册就绪（通过 `ResizeObserver`、`useLayoutEffect` 或等价机制确认），再执行 **Viewport state** 平移计算和高亮。在同一个同步执行栈里强行计算 `getBoundingClientRect()` 会因目标 DOM 尚未渲染完毕而拿到错误的边界框，导致定位偏移或高亮失败。

---

## 3. 非目标

本次不做以下能力：

- **OS 级 always-on-top**：不使用 Tauri `setAlwaysOnTop` 或等价 API，置顶只表示浮层 z-index 优先级。
- **Tauri 独立窗口**：不创建 `WebviewWindow`，不处理动态窗口 label、窗口生命周期、跨窗口事件同步。
- **标签 / 标签筛选**：本版本不包含标签筛选能力。v1.4.1 中关于标签筛选的旧规划已被当前路线图取代，不再作为 v1.4.5 的范围。
- **直接编辑**：撕下视图不提供标题或正文编辑入口，用户必须回到画布编辑。
- **第二份 Note 数据**：不为撕下视图创建副本，不写入 `StorageData`。
- **持久化撕下状态**：撕下视图的显隐和位置不持久化到 `data.json`，应用重启后清空。
- **画布选区 / 多选 / 右键菜单 / 归拢参与**：撕下视图不参与画布的框选、Ctrl+点击多选、右键菜单操作、归拢、拆分、合并。
- **全局事件广播**：不使用全局事件推送所有 Note 状态到撕下视图；只定向订阅当前撕下 Note 的变更。
- **Undo / Redo 接入**：撕下视图的打开 / 关闭不进入通用历史，不影响 **Domain state** 可逆变更。
- **废纸篓管理入口**：不在 **Trash（废纸篓）** 里为撕下视图提供额外管理入口；撕下视图只跟随对应 **Note** 的存在性自动关闭。
- **重启恢复**：不承诺应用重启后恢复所有撕下窗口。
- **多窗口失焦保护**：v1.4.5 为单窗口浮层，不涉及独立窗口之间的失焦隐藏保护；该问题推迟到 `v1.4.6`。

## 4. 业务边界决策

### 4.1 撕下便签的语义

撕下便签不是复制，也不是剪切。它只是为同一个 **Note** 创建一个额外的只读渲染视图。

- 画布中的 **Note** 是唯一事实来源。
- 撕下视图只读，不提供标题或正文编辑入口。
- 用户在画布中修改 **Note** 后，撕下视图同步映射最新内容。
- 关闭或贴回撕下视图，不应创建新 **Note**，也不应删除原 **Note**。
- 撕下视图本身默认不进入持久化数据。

### 4.2 浮层容器设计

- 浮层容器固定在主窗口内，位于画布层之上、顶部菜单栏之下。
- 浮层容器支持拖拽移动每个撕下视图的位置。
- 浮层容器支持关闭单个撕下视图。
- 浮层容器默认不占据画布空间，不影响画布的 **Viewport state**。

### 4.3 同步机制

- 撕下视图订阅当前 **Note** 在 `useStore` 中的领域切片。
- 当 **Note** 的标题、正文、颜色、折叠状态等字段变更时，撕下视图重新渲染。
- 当 **Note** 被软删除或永久删除时，撕下视图自动关闭。
- 不使用全局事件广播；同步通过 Zustand 订阅机制实现。

### 4.4 定位到画布所在的 fallback

- 如果便签所属 **Board** 已不存在，定位操作不切换 **Board**，在当前 **Board** 中搜索并高亮该便签（如果存在）。
- 如果当前 **Board** 中也没有该便签，定位操作静默无动作。
- 如果便签不存在（已被永久删除），定位操作静默无动作。

### 4.5 贴回画布的语义

"贴回画布"不表示复制或粘贴一份新便签，只表示收回这个镜像视图。关闭撕下视图与贴回画布行为等价。

### 4.6 置顶层级

- 浮层默认 z-index 层级低于置顶状态。
- 点击"置顶"后，该撕下视图的 z-index 提升到所有其他撕下视图之上。
- 再次点击"置顶"取消提升，恢复默认层级。
- 置顶状态不持久化，应用重启后清空。

## 5. 实施约束

### 5.1 只读分离视图

撕下视图是只读的。组件内部不渲染任何输入框、文本编辑器或可交互的编辑控件。用户必须回到画布中的原始 **Note** 进行编辑。

### 5.2 不重复 Note

同一 **Note** 在任意时刻最多只能有一个撕下视图。触发撕下操作时，如果该 **Note** 已有撕下视图，应聚焦并激活现有浮层，不创建新实例。

### 5.3 不持久化分离状态

撕下视图的显隐状态、浮层位置、置顶状态均不写入 `StorageData`。应用重启后，所有撕下视图清空。

### 5.4 不直接编辑

撕下视图不提供任何修改 **Domain state** 的入口。按钮行为只影响 **Viewport state** 或 **UI state**，或仅关闭浮层。

### 5.5 不参与画布交互

撕下视图不参与画布的以下交互：

- 框选（marquee select）
- Ctrl + 点击多选
- 右键菜单
- 归拢、拆分、合并
- 拖拽移动
- 编辑尺寸偏好

### 5.6 不全局广播所有便签状态

撕下视图只订阅当前撕下 **Note** 的领域切片变更。不订阅、不接收、不处理其他 **Note** 的状态变更。

### 5.7 工程约束：Portal、订阅与渲染时序

以下三项约束源于主窗口内浮层的技术特性，必须在实现中严格遵守：

**5.7.1 Portal 渲染与层叠上下文安全**

`DetachedNoteOverlay` 必须通过 `createPortal` 渲染到 `<body>` 下的 `#overlay-root` 节点。禁止将浮层直接渲染在画布组件树内部，以避免画布的 `transform`、`opacity`、`will-change` 等 CSS 属性创建层叠上下文导致 z-index 失效。

**5.7.2 精确 Zustand 订阅**

撕下视图的选择器必须精确提取只读所需的字段（如 `title`、`content`、`color`、`isCollapsed`），配合 `useShallow` 或 `React.memo` + 自定义 `areEqual` 进行浅比较。禁止使用返回整个便签对象的选择器，以避免其他便签状态变更引起的不必要重渲染。

**5.7.3 定位操作的渲染时序感知**

`appController.locateDetachedNote` 必须感知 React 渲染周期。跨 Board 切换后，必须等待目标画布和 Note DOM 注册就绪（通过 `ResizeObserver`、`useLayoutEffect` 或等价机制确认）后，再执行 **Viewport state** 平移计算和高亮。禁止在切换 ViewMode/Board 的同步执行栈中直接计算 `getBoundingClientRect()`。

## 6. 技术设计

### 6.1 组件拆分

从 `NoteCard` 中抽取纯展示部分为独立模块：

```ts
// src/components/note-render/NoteVisuals.tsx
// 职责：便签背景、阴影、边框、颜色计算、标题与正文只读展示、折叠态展示
```

`NoteVisuals` 应与 `NoteCard` 共享同一份视觉渲染能力，避免两套视觉逻辑分叉。

### 6.2 浮层容器（Portal 渲染）

`DetachedNoteOverlay` 必须通过 React `createPortal` 渲染到 `<body>` 下的专属 `#overlay-root` 节点，而不是直接渲染在画布组件树内。

原因：主画布及其父级节点在缩放（`transform: scale(...)`）、透明度调整或 `will-change` 等场景下会创建新的层叠上下文（Stacking Context）。如果浮层容器与画布处于同一 DOM 层级树，即使设置极高的 z-index，浮层仍会被画布的层叠上下文压制。通过 Portal 物理分离 DOM 树，浮层与画布处于不同的层叠上下文，置顶切换只需维护局部数组顺序和内联 z-index 即可。

```ts
// src/components/DetachedNoteOverlay.tsx
// 职责：通过 createPortal 渲染到 #overlay-root，管理多个撕下视图的容器、拖拽移动、关闭、置顶切换
// 容器本身仍处于同一 React/Zustand 运行时，可直接订阅 store 状态
```

HTML 入口需确保 `<body>` 下存在 `<div id="overlay-root" />` 节点，位于画布 DOM 之外。

### 6.3 UI state 扩展

在 **UI state** 中新增：

```ts
type DetachedNote = {
  noteId: string;
  position: { x: number; y: number };
  isPinned: boolean;
};

// 在 UI state 中添加
detachedNotes: DetachedNote[];
```

### 6.4 Store 写入

- 撕下操作：`appController.detachNote(noteId)`，向 `detachedNotes` 追加记录。
- 关闭操作：`appController.closeDetachedNote(noteId)`，从 `detachedNotes` 移除记录。
- 移动操作：`appController.moveDetachedNote(noteId, position)`，更新 `detachedNotes` 中的位置。
- 置顶切换：`appController.toggleDetachedNotePin(noteId)`，切换 `isPinned` 状态。
- 定位操作：`appController.locateDetachedNote(noteId)`，切换 **ViewMode**、更新 **Viewport state** 和 **UI state**。

### 6.5 同步机制（精确订阅）

**禁止**在撕下视图组件中直接使用 `useStore(state => state.notesById[noteId])` 作为选择器。Zustand 默认使用严格相等（`===`）比较，当画布中其他便签发生状态变更（如归拢、拆分）导致 `notesById` 对象引用更新时，即使当前 `noteId` 对应的数据未变，撕下视图也会被触发不必要的重渲染。

正确做法：选择器必须精确提取只读视图所需的字段，配合浅比较或 memoization：

```ts
// 方案 A：精确字段选择 + useShallow
import { useShallow } from 'zustand/shallow';

const noteSnapshot = useStore(
  useShallow(state => {
    const note = state.notesById[noteId];
    if (!note) return { exists: false as const };
    return {
      exists: true as const,
      title: note.title,
      content: note.content,
      color: note.color,
      isCollapsed: note.isCollapsed,
    };
  })
);

if (!noteSnapshot.exists) return null;

// 方案 B：NoteVisuals 组件使用 React.memo + 自定义 areEqual
const NoteVisuals = React.memo(NoteVisualsImpl, (prev, next) => {
  return prev.title === next.title
    && prev.content === next.content
    && prev.color === next.color
    && prev.isCollapsed === next.isCollapsed;
});
```

同时需要检测便签是否存在（软删除或永久删除后 `notesById` 中移除），存在性变化时触发浮层自动关闭：

```ts
const noteExists = useStore(state => state.notesById[noteId] !== undefined);
// noteExists 从 true 变为 false 时，触发 closeDetachedNote
```

### 6.6 关闭时机

以下情况下撕下视图自动关闭：

- 用户点击"贴回画布"按钮。
- 用户点击关闭按钮。
- 便签在画布被软删除或永久删除。
- 应用重启。

## 9. 验收标准

### 9.1 撕下操作

- 在画布便签右键菜单中点击"撕下便签"后，主窗口上方出现该便签的只读浮层。
- 同一便签再次触发撕下操作时，聚焦并激活现有浮层，不创建新实例。
- 撕下视图无法直接修改便签标题或正文。

### 9.2 内容同步

- 在画布修改便签标题后，撕下视图同步展示最新标题。
- 在画布修改便签正文后，撕下视图同步展示最新正文。
- 在画布改变便签颜色后，撕下视图同步展示最新颜色。

### 9.3 三个按钮

- 点击"定位到画布所在"后，主窗口切回便签所属 **Board**（如果不在），平移视口使便签居中，高亮并选中原便签。
- 点击"置顶"后，该撕下视图的 z-index 提升到所有其他撕下视图之上；再次点击取消提升。
- 点击"贴回画布"后，撕下视图关闭，不创建副本，不删除原便签。

### 9.4 浮层交互

- 浮层支持拖拽移动位置。
- 浮层支持关闭单个视图。
- 浮层不遮挡主窗口顶部菜单栏。

### 9.5 自动关闭

- 便签在画布被软删除后，对应撕下视图自动关闭。
- 便签在画布被永久删除后，对应撕下视图自动关闭。
- 应用重启后，所有撕下视图清空。

### 9.6 边界保护

- 撕下视图不参与画布的框选、多选、右键菜单、归拢、拆分、合并。
- 撕下视图不订阅或广播其他便签的状态。
- 撕下视图的打开 / 关闭不进入通用 Undo/Redo 历史。
- `npm run typecheck`、`npm run test`、`npm run build` 全部通过。

### 9.7 工程约束验收

- 撕下视图的 DOM 节点挂载在 `#overlay-root` 下，不在画布 DOM 子树内。
- 在画布处于缩放状态（`transform: scale(...)`）时，撕下视图仍能正确显示在画布之上，不被画布层叠上下文压制。
- 切换其他便签颜色或移动其他便签时，已打开的撕下视图不发生不必要的重渲染（可通过 React DevTools Profiler 验证）。
- 跨 Board 定位操作后，便签高亮和视口平移准确，不出现定位偏移或高亮失败。
- 同时打开多个撕下视图时，拖拽画布中的其他便签不会导致撕下视图帧率明显下降。

## 10. 风险

- 从 `NoteCard` 抽取 `NoteVisuals` 时，如果视觉逻辑与 `NoteCard` 的交互逻辑耦合过深，可能导致抽取困难或视觉分叉。
- Portal 渲染虽然解决了层叠上下文问题，但 `#overlay-root` 与画布的 DOM 物理分离后，拖拽浮层的坐标计算需要基于全局视口而非画布局部坐标系，增加了坐标转换的复杂度。
- 精确 Zustand 订阅如果字段选择不够精细，在高频编辑场景下仍可能产生不必要的重渲染；需要通过 Profiler 持续验证。
- "定位到画布所在"的渲染时序依赖 `ResizeObserver` 或 `useLayoutEffect` 的就绪回调，如果目标 Board 的画布渲染链路存在异步延迟（如懒加载），可能导致定位操作等待时间过长或超时失败。
- 撕下视图自动关闭的时机如果与软删除的 Undo/Redo 交互，可能出现便签恢复但撕下视图已关闭的情况，需要评估是否需要恢复撕下视图。
- `createPortal` 将浮层挂载到 `#overlay-root` 后，浮层不再受画布容器的裁剪（`overflow: hidden`）约束，如果浮层位置计算不当可能溢出窗口边界。

## 11. 已采纳的关键决策

### 11.1 主窗口内浮层，非独立窗口

`v1.4.5` 只在主窗口内实现浮层原型，不引入 Tauri 多窗口复杂度。OS 级 always-on-top 独立窗口推迟到 `v1.4.6`。

### 11.2 置顶只表示浮层 z-index 优先级

v1.4.5 的"置顶"行为仅切换浮层的 z-index 层级优先级，不涉及操作系统级窗口置顶。

### 11.3 标签筛选不在范围内

标签筛选功能不在 v1.4.5 范围内。v1.4.1 中关于标签筛选的旧规划已被当前路线图取代。

### 11.4 不持久化撕下状态

撕下视图的显隐、位置、置顶状态均不持久化到 `StorageData`。应用重启后清空。

### 11.5 不全局广播便签状态

撕下视图只订阅当前撕下 **Note** 的领域切片变更，不订阅或广播其他便签状态。

## 12. 开放问题

这些问题不阻塞 v1.4.5 规划落地，但实施前需要在对应 commit 中确认：

- **入口位置**：默认入口暂定为画布便签右键菜单的"撕下便签"，是否还需要在便签工具区提供图标按钮，留到实现时结合现有交互密度判断。
- **初始位置**：撕下浮层首次出现的位置应尽量靠近原便签但不遮挡顶部菜单栏；如果原便签靠近窗口边缘，需要有边界夹取策略。
- **数量上限**：规划允许同时显示多个撕下视图，但是否需要数量上限暂不预设，先通过 UI state 的数据结构保持可控。
- **软删除撤销后的恢复**：便签被软删除时撕下视图自动关闭；如果用户随后撤销软删除，是否自动恢复撕下视图暂不承诺，默认不恢复。

`v1.4.5` 在主窗口内实现撕下便签的只读浮层原型，验证撕下语义、三个按钮行为、内容同步和浮层交互，为 `v1.4.6` Tauri 独立窗口版本打下基础。
