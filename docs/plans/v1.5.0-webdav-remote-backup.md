# SoNotes v1.5.0 实施计划：WebDAV 远端备份

---

## 1. 背景

`v1.4.9` 已经完成本地 zip 备份 / 恢复能力：备份包包含 `data.json`、`manifest.json` 与被 **Domain state（领域状态）** 引用的图片文件，并在恢复前执行 zip entry 路径、manifest、`StorageData` 契约、图片文件 hash 与失败回滚校验。

`v1.5.0` 的主题是 **WebDAV 远端备份**。本版本在不改变本地 zip 备份包格式的前提下，把 WebDAV 作为远端备份仓库，用于上传、列出、下载和恢复带时间戳的 zip 快照。

本版本只做远端备份与显式恢复，不做实时同步、多端合并、便签级冲突解决或远端运行时数据源。

---

## 2. 当前代码基线

### 2.1 已存在的复用点

- `src-tauri/src/backup.rs`：已有本地 zip 备份 / 恢复实现，包含 `create_local_backup`、`restore_local_backup`、`BackupManifest`、`BackupResult`、`RestoreResult`、zip entry 路径校验、`StorageData` 契约校验与测试。
- `src/services/backup/BackupService.ts`：已有前端本地备份服务层，通过 Tauri `invoke` 调用 Rust 侧备份 / 恢复命令。
- `src/services/backup/BackupService.test.ts`：已有本地备份服务层测试。
- `src-tauri/src/lib.rs`：已有 Tauri 命令注册点，目前注册本地备份 / 恢复命令。

### 2.2 当前不存在的能力

- 当前没有 `src-tauri/src/webdav.rs`。
- 当前没有 `src/services/backup/WebDavBackupService.ts`。
- 当前没有 WebDAV 配置面板、远端备份列表或远端恢复入口。
- 当前 `src-tauri/Cargo.toml` 没有 HTTP / WebDAV 客户端依赖。
- 当前 `package.json` 没有 WebDAV 前端客户端依赖。

因此，v1.5.0 应按“新增 WebDAV 模块与服务层”设计，而不是扩展一个已存在的 WebDAV 实现。

## 3. 目标

### 3.1 WebDAV 配置

- 用户可配置 WebDAV 服务地址、用户名、密码或应用令牌、远端目录。
- 配置保存在本地应用配置中，不写入 zip 备份包。
- 配置持久化必须有明确技术接口，包括加载、保存和清除配置；前端 UI 不得只保留内存表单状态。
- 凭据优先保存到系统密钥链；如第一版暂不接入系统密钥链，必须明确本地配置文件路径、非敏感字段与凭据字段边界，并允许用户选择“不记住密码”。
- 提供测试连接入口，验证地址可达性、鉴权结果与远端目录可用性。
- 测试连接失败时给出明确提示，例如网络不可达、鉴权失败、目录不可访问或服务不支持所需 WebDAV 方法。

### 3.2 创建远端备份

- 用户通过明确入口触发远端备份。
- 远端备份必须先复用 v1.4.9 本地备份流程生成一个 zip 快照。
- 创建远端备份前必须先刷新当前状态到磁盘，复用本地 zip 备份入口已有的 `persistenceFacade.flushNow()` gate；刷新失败时必须中止远端备份，不得上传可能过期的 `data.json`。
- 远端备份按钮不得要求用户再选择本地保存位置；本地临时快照由 Rust 侧创建在应用缓存目录的 WebDAV 专用临时子目录中。
- zip 快照上传到用户配置的 WebDAV 目录。
- 上传到远端的文件名必须由 Rust 侧按统一规则生成或规范化，不能直接沿用调用方传入的本地文件名；当前本地默认名 `sonotes-backup-${timestamp}.zip` 必须转换为远端规范名。
- 上传不得覆盖旧备份；HTTP 上传必须使用 `If-None-Match: *` 或等价防覆盖机制，遇到同名冲突时应重新生成远端文件名后重试，而不是覆盖已有对象。
- 上传成功后默认清理该临时快照；上传失败时临时快照只保留到本次错误处理完成或下次启动清理，不进入用户可见备份目录。
- 上传失败不得影响本地保存，也不得破坏用户已有的本地 zip 备份。

### 3.3 列出远端备份

- 用户可手动刷新 WebDAV 目录中的远端备份列表。
- 列表只展示符合 `SoNotes_Backup_YYYYMMDDHHMMSS.zip` 命名约定的备份包。
- 列表展示文件名、修改时间、大小和可读状态。
- 列表操作不得触发自动下载、自动恢复、自动合并或本地数据覆盖。

### 3.4 从远端备份恢复

- 用户必须显式选择某个远端 zip 备份包。
- 应用先把远端备份包下载到本地临时位置。
- 下载阶段必须设置最大下载字节数；`Content-Length` 超限时拒绝下载，`Content-Length` 缺失时按流式累计字节数限制，超限后立即中止并清理临时文件。
- 下载完成后，前端使用下载 token 换取受控恢复路径，并复用 v1.4.9 的本地 zip 恢复校验与恢复流程。
- 恢复前必须二次确认，并明确提示当前本地数据将被替换。
- 临时下载文件必须有 Rust 侧生命周期管理，使用下载 token、过期清理或显式清理命令，不能只依赖前端记住临时路径。
- 恢复成功、恢复失败、用户取消或应用重启后再次启动清理时，都必须保持当前本地数据不被破坏，并清理可识别的临时下载文件。

### 3.5 可选定时上传

- 第一版可提供定时上传开关，但必须默认关闭。
- 定时上传只能在 `persistenceFacade.flushNow()` 成功后创建新 zip 快照并上传到远端。
- 定时上传不得从远端自动下载、自动恢复或覆盖本地数据。
- 最近一次定时上传结果应可见，避免用户误以为远端备份总是成功。

---

## 4. 非目标

本版本明确不做：

- 实时同步。
- 自动拉取远端数据并覆盖本地。
- 多端自动合并。
- 便签级冲突解决。
- CRDT、向量时钟或操作日志合并。
- 把远端文件作为应用运行时数据源。
- 增量备份。
- 远端备份包内容浏览、编辑或合并。
- 多 WebDAV 账户管理。
- 端到端加密。

---

## 5. 业务边界决策

### 5.1 WebDAV 是远端备份仓库

WebDAV 只存放由 SoNotes 生成的完整 zip 快照。应用运行时的数据真实来源仍是本地 **Domain state** 与本地持久化数据。

原因：

- 当前应用没有多端操作日志或冲突解决机制。
- 本地 zip 备份 / 恢复已具备完整校验与失败回滚边界。
- 用户应明确知道自己是在上传备份、下载备份或恢复备份。

### 5.2 远端备份复用本地 zip 格式

远端备份不定义新的数据格式。上传单元仍是 v1.4.9 已实现的 zip 备份包；远端对象名必须单独规范化为 `SoNotes_Backup_YYYYMMDDHHMMSS.zip`。

当前本地备份入口默认文件名是 `sonotes-backup-${timestamp}.zip`，且 Rust 本地备份流程只使用调用方传入路径，不强制文件名。因此 WebDAV 上传不得把本地文件 basename 当作远端列表识别依据，必须在 Rust 侧从本地文件名或备份包元数据生成远端规范名。

远端备份创建时的本地 zip 落点固定为应用缓存目录下的 WebDAV 临时备份目录，例如 `<app-cache>/webdav-backups/pending/`。该目录只服务远端上传，不作为用户可见备份目录；上传成功必须清理，上传失败允许短暂保留用于错误处理，但必须纳入启动清理和过期清理。

原因：

- 本地 zip 格式已经包含 `data.json`、`manifest.json` 与图片文件校验信息。
- 远端恢复可以下载后复用同一套本地恢复校验。
- 避免远端能力反向改变本地备份包契约。

### 5.3 远端恢复必须先下载到本地临时位置

远端恢复流程必须是：

```text
选择远端备份 → 校验远端文件名 → 下载到本地临时位置并登记 token → 前端用 token 换取受控本地路径 → 调用本地 zip 恢复校验 → 确认后恢复本地数据 → 清理临时文件
```

不允许直接从 WebDAV 流式写入当前数据目录。

本计划采用唯一链路：WebDAV 模块只负责远端传输、远端文件名校验、下载 token、临时文件登记与清理；真正恢复仍由既有 `backup::restore_local_backup` 流程执行。为避免前端持有裸临时路径，Rust 侧应提供 `resolve_downloaded_backup(download_token) -> LocalBackupPathResult` 或等价受控接口，只在 token 有效且路径位于 WebDAV 临时目录时返回可恢复路径；恢复完成、失败或取消后由前端调用 `cleanup_downloaded_backup(download_token)`。

下载 token 必须有明确状态机：`ready` 表示下载完成且可解析，`resolved` 表示已换取一次受控路径并锁定，`cleaned` 表示临时文件已清理或确认不存在。`resolve_downloaded_backup` 必须是一次性的：同一 token 第二次 resolve 应拒绝；`cleanup_downloaded_backup` 应幂等，但 cleanup 后 token 必须失效，且不得删除 WebDAV 临时目录之外的任何路径。

不新增 `webdav_restore_downloaded_backup`，除非明确把它定义为 `backup::restore_local_backup` 的受控包装并调整“WebDAV 命令不直接修改数据”的边界；v1.5.0 计划默认不采用该方案。

### 5.4 远端目录不参与运行时仲裁

启动仲裁只应在本地 WAL、本地磁盘数据和当前持久化机制之间选择可信数据。WebDAV 目录不得参与启动仲裁，也不得在应用启动时自动覆盖本地数据。

### 5.5 配置不进入备份包

WebDAV 服务地址、用户名、密码或应用令牌属于本机配置，不是 **Domain state**，不得写入 `data.json` 或 zip 备份包。

凭据存储策略必须在实现前明确：

- 优先使用系统密钥链保存密码或应用令牌，本地配置文件只保存 WebDAV 地址、用户名、远端目录和密钥链引用。
- 如第一版暂不接入系统密钥链，必须明确本地配置文件路径、权限假设、是否加密、迁移方案和用户可选择的“不记住密码”模式。
- 错误、日志、测试快照和界面提示必须做脱敏，不能包含密码、应用令牌、完整鉴权头或带凭据的 URL。
- 前端传入 Tauri 命令的配置应尽量只包含非敏感字段；如必须传递密码或应用令牌，该值只允许用于当前请求，不得被命令日志化或返回给前端错误对象。

配置持久化必须形成闭环：Rust 侧提供加载、保存和清除配置命令；前端打开 WebDAV 配置界面时先加载已保存配置，用户保存后重启应用仍能恢复非敏感字段和密钥链引用。用户清除配置时，`clearConfig` 必须删除对应系统密钥链 secret 或会话凭据，而不只是删除本地配置中的引用；清除后不得残留可继续鉴权的凭据引用。

### 5.6 WebDAV 传输必须默认使用 HTTPS

WebDAV URL 默认必须使用 `https://`。只有开发和本机调试场景允许 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]`。

WebDAV base URL 还必须拒绝 `userinfo`、`query` 与 `fragment`。例如 `https://user:token@example.com/path?token=...` 不应被接受；凭据只能通过配置字段或系统密钥链传入，不能藏在 URL 中，也不能进入日志或错误提示。

原因：

- WebDAV 请求会携带密码、应用令牌或鉴权头。
- 明文 HTTP 会让凭据和备份包在传输中暴露。
- 本机开发例外不应扩展到局域网明文地址。

## 6. 技术设计

### 6.1 Rust 侧 WebDAV 模块

新增 `src-tauri/src/webdav.rs`。

建议职责：

- 规范化 WebDAV base URL 与远端目录。
- 校验 WebDAV URL scheme，默认拒绝非 HTTPS URL，仅允许本机 HTTP 开发例外。
- 拒绝 base URL 中的 `userinfo`、`query` 与 `fragment`，避免凭据或令牌藏入 URL。
- 加载、保存和清除 WebDAV 配置；敏感凭据优先经系统密钥链保存，非敏感字段保存到本地应用配置；清除配置时删除对应密钥链 secret 或会话凭据。
- 发送测试连接请求。
- 创建远端目录或检查远端目录可用性，并严格校验远端目录参数。
- 在应用缓存目录创建 WebDAV 专用临时快照，并以防覆盖语义上传到远端目录。
- 列出远端目录中的备份 zip 文件。
- 下载指定远端 zip 文件到本地临时位置。
- 对远端下载执行传输阶段大小上限，覆盖 `Content-Length` 已知和未知两种情况。
- 校验远端文件名参数，只允许规范 basename，不接受路径段、URL 编码路径段或目录跳转。
- 管理 WebDAV 下载临时文件生命周期，包括 token 登记、一次性 resolve、显式清理、过期清理和启动清理。
- 将网络、鉴权、目录、超时、解析和传输错误转换为结构化错误。

建议命令：

```rust
webdav_test_connection(config: WebDavConfig) -> WebDavConnectionResult
webdav_load_config() -> WebDavConfigLoadResult
webdav_save_config(config: WebDavConfigSaveRequest) -> WebDavConfigSaveResult
webdav_clear_config() -> WebDavConfigClearResult
webdav_create_remote_backup(config: WebDavConfig) -> WebDavUploadResult
// 第一版默认不注册；若未来实现，必须先校验 local_zip_path 是 SoNotes zip 备份。
webdav_upload_backup(config: WebDavConfig, local_zip_path: String) -> WebDavUploadResult
webdav_list_backups(config: WebDavConfig) -> Vec<WebDavRemoteBackup>
webdav_download_backup(config: WebDavConfig, remote_file_name: String) -> WebDavDownloadResult
resolve_downloaded_backup(download_token: String) -> LocalBackupPathResult
cleanup_downloaded_backup(download_token: String) -> WebDavCleanupResult
```

`webdav_load_config`、`webdav_save_config` 和 `webdav_clear_config` 用于配置持久化闭环。保存请求应区分非敏感字段与凭据字段：非敏感字段包括 WebDAV 地址、用户名、远端目录、是否记住密码、密钥链引用；密码或应用令牌如需传入 Rust，只能用于写入系统密钥链或当前会话，不得原样写入普通配置文件或返回给前端。`webdav_clear_config` 必须删除对应密钥链 secret 或会话凭据，再删除本地配置引用；如果密钥链删除失败，必须返回可见错误，不能假装清除成功。

`webdav_create_remote_backup` 用于“创建远端备份”入口：前端必须先执行 `persistenceFacade.flushNow()`，只有刷新成功才调用该命令；Rust 侧随后在应用缓存目录生成临时 zip，再上传并按结果清理，前端不提供本地目标路径。远端 `PUT` 必须带 `If-None-Match: *` 或等价防覆盖语义；若服务器返回同名冲突，应等待进入下一秒后重新生成 `SoNotes_Backup_YYYYMMDDHHMMSS.zip` 并重试有限次数，最终仍冲突时返回结构化错误。`webdav_upload_backup` 的 `local_zip_path` 只用于“上传用户已存在本地备份”的可选场景；第一版默认不注册该命令，避免形成任意本地文件上传口。若未来实现并注册，Rust 必须先按本地恢复同级别校验确认该路径是 SoNotes zip 备份，包括读取 `manifest.json`、校验 `app === "SoNotes"`、`formatVersion`、`data.json` 契约和 zip entry 路径安全；校验失败不得上传。

`webdav_download_backup` 必须先校验 `remote_file_name` 是规范 basename，再下载到安全临时位置，并返回下载 token；不返回裸本地路径。远端下载的传输阶段最大字节数建议定义为 `MAX_WEBDAV_BACKUP_DOWNLOAD_BYTES = 1024 * 1024 * 1024`（1 GiB），这是压缩 zip 文件下载上限；它不能替代 `backup.rs` 中对 `manifest.json`、`data.json`、单个图片文件和图片文件总量的解压后上限。下载前如果响应 `Content-Length` 超过该上限，应拒绝写入；如果缺少 `Content-Length`，必须在流式写入过程中累计字节数并在超限时中止、删除临时文件并返回超限错误。`resolve_downloaded_backup` 只在 token 有效、未过期、尚未 resolve 且路径位于 WebDAV 临时目录时返回受控本地路径；resolve 成功后 token 进入锁定状态，不能再次 resolve。WebDAV 模块不执行恢复写入。

### 6.2 Rust 依赖

当前 `src-tauri/Cargo.toml` 没有 HTTP 客户端依赖。建议新增 `reqwest`，由 Rust 侧直接实现 WebDAV 所需 HTTP 方法；同时新增 `quick-xml` 或同类结构化 XML 解析依赖，用于解析 `PROPFIND` 返回的 `multistatus`。

原因：

- WebDAV 在本版本只需要连接测试、上传、列出、下载，不需要完整 WebDAV 服务端能力。
- `PROPFIND`、`PUT`、`GET` 等方法可通过 HTTP 客户端显式实现。
- `PROPFIND` 响应必须按 XML 结构解析，处理 namespace、HTTP status、目录项排除、大小与修改时间缺失，不允许用字符串拼接或正则粗略解析。
- Rust 侧处理凭据、路径、超时与错误映射更容易保持前端服务层简洁。

### 6.3 Tauri 命令注册

在 `src-tauri/src/lib.rs` 中新增 `webdav` 模块声明并注册 WebDAV 命令。

要求：

- WebDAV 命令与 `backup::create_local_backup`、`backup::restore_local_backup` 并列注册。
- WebDAV 命令不直接修改当前数据目录中的 `data.json`、`attachments/`、WAL 或前端 **Domain state**；它只允许读写应用缓存目录下的 WebDAV 临时备份文件。
- 本地恢复仍只通过既有恢复流程完成。

### 6.4 前端 WebDAV 服务层

新增 `src/services/backup/WebDavBackupService.ts`。

建议 API：

```ts
testConnection(config: WebDavConfig): Promise<WebDavConnectionResult>
loadConfig(): Promise<WebDavConfigLoadResult>
saveConfig(config: WebDavConfigSaveRequest): Promise<WebDavConfigSaveResult>
clearConfig(): Promise<WebDavConfigClearResult>
createRemoteBackup(config: WebDavConfig): Promise<WebDavUploadResult>
uploadBackup(config: WebDavConfig, localZipPath: string): Promise<WebDavUploadResult>
listBackups(config: WebDavConfig): Promise<WebDavRemoteBackup[]>
downloadBackup(config: WebDavConfig, remoteFileName: string): Promise<WebDavDownloadResult>
resolveDownloadedBackup(downloadToken: string): Promise<LocalBackupPathResult>
cleanupDownloadedBackup(downloadToken: string): Promise<WebDavCleanupResult>
```

要求：

- 保持与 `BackupService.ts` 类似的薄封装风格。
- 配置表单必须通过 `loadConfig`、`saveConfig` 和 `clearConfig` 与 Rust 持久化接口闭环，不能只依赖组件内存状态。
- 不在前端直接实现 WebDAV HTTP 逻辑。
- 不在服务层拼接不受控路径。
- `createRemoteBackup` 是创建远端备份的默认入口，不接受本地路径参数；调用前必须先通过 `persistenceFacade.flushNow()` 刷新当前状态，失败时不调用 Rust 命令。
- `uploadBackup` 只用于上传用户已存在的本地备份；如果第一版没有该 UI 入口，服务层测试不应把它当作创建远端备份流程。
- `downloadBackup` 返回下载 token，不返回本地临时路径；服务层必须通过 `resolveDownloadedBackup` 获取可传给本地恢复流程的受控路径。
- 对 Tauri 返回错误做面向界面的错误分类。

### 6.5 数据管理区入口

在现有数据管理区域扩展 WebDAV 入口：

- WebDAV 配置表单。
- 保存配置、清除配置和重新加载配置入口。
- 测试连接按钮。
- 创建远端备份按钮。
- 刷新远端备份列表按钮。
- 从选中远端备份覆盖恢复按钮。
- 可选定时上传开关与频率设置。

交互要求：

- WebDAV 操作进行中禁用相关按钮，避免并发触发。
- 创建远端备份时显示“正在保存当前数据 / 正在创建本地备份 / 正在上传 / 上传完成 / 上传失败”。
- 创建远端备份和定时上传都必须先调用 `persistenceFacade.flushNow()`；刷新失败时展示“当前数据尚未成功写入磁盘，请稍后重试”，不得继续创建或上传远端备份。
- 远端恢复时显示“正在下载 / 正在校验 / 正在恢复 / 恢复完成 / 恢复失败”。
- 从远端恢复必须复用 v1.4.9 的持久化控制顺序：刷新当前状态、暂停自动持久化、执行恢复、替换前端状态、清理运行态、恢复自动持久化。

### 6.6 远端备份命名与过滤

远端目录默认建议：

```text
SoNotes_Backups/
```

远端目录配置规则：

- 空值时默认使用 `SoNotes_Backups/`，并由测试连接或首次上传时检查，不存在则尝试自动创建。
- 第一版只允许单级相对目录，例如 `SoNotes_Backups/`；不支持 `foo/bar/` 这类嵌套目录，避免递归 `MKCOL` 在不同 WebDAV 服务上的兼容性差异。
- 不接受完整 URL、盘符路径或以 `/`、`\` 开头的绝对路径。
- 拒绝 `..`、空段、反斜杠、空字节、URL 编码路径段和额外目录分隔符；目录分隔符统一为尾部单个 `/`。
- 保存配置时应规范化尾部 `/`，例如用户输入 `SoNotes_Backups` 后保存为 `SoNotes_Backups/`。

远端备份文件只识别：

```text
SoNotes_Backup_YYYYMMDDHHMMSS.zip
```

实现约束：

- Rust 侧必须定义严格文件名正则 `^SoNotes_Backup_\d{14}\.zip$`，并保证匹配结果是 basename。
- 列出远端文件时应过滤不符合命名约定的文件，避免用户目录中的无关文件被当作备份包。
- 上传时必须把当前本地默认名 `sonotes-backup-${timestamp}.zip` 规范化为远端命名，或从备份包元数据生成远端命名，确保上传后能被远端列表识别。
- 上传时不得依赖秒级命名天然唯一；必须通过 HTTP 防覆盖机制或远端存在检测确保不会覆盖旧备份。同名冲突后保持 `SoNotes_Backup_YYYYMMDDHHMMSS.zip` 格式不变，等待下一秒后重新生成文件名并有限重试，不引入毫秒或序号后缀，避免放宽正则。
- 下载时不得信任前端传入的 `remote_file_name`；Rust 侧必须拒绝包含 `/`、`\`、`..`、空字节、URL 编码路径段或非规范扩展名的值。
- 远端命名不得包含 `:`，避免 Windows 文件名不友好字符影响下载后的临时文件处理。

### 6.7 错误处理

WebDAV 错误应映射为稳定的用户可理解提示：

- “WebDAV 地址不可访问”。
- “WebDAV 鉴权失败”。
- “远端备份目录不可用”。
- “远端备份列表读取失败”。
- “远端备份上传失败，本地数据未受影响”。
- “远端备份下载失败，本地数据未受影响”。
- “备份文件校验失败，本地数据未被修改”。
- “远端已存在同名备份，请稍后重试”。
- “远端备份超过允许大小，本地数据未受影响”。

错误提示不得包含密码、应用令牌或完整鉴权头。

传输安全错误应映射为明确提示，例如“WebDAV 地址必须使用 HTTPS，只有本机开发地址允许 HTTP”。

URL 规范化错误应映射为明确提示，例如“WebDAV 地址不能包含用户名、密码、查询参数或片段”。

## 7. 安全与可靠性要求

- 所有远端恢复都必须由用户显式触发。
- WebDAV URL 默认必须使用 HTTPS，仅允许本机 HTTP 开发例外。
- WebDAV base URL 必须拒绝 `userinfo`、`query` 与 `fragment`，凭据不得通过 URL 传递。
- 下载后的 zip 必须通过 v1.4.9 本地恢复的全部校验后才允许恢复。
- 远端下载必须有传输阶段最大字节数限制，超限时中止并清理临时文件。
- 下载失败、校验失败或恢复失败时不得修改当前本地数据。
- 创建远端备份使用应用缓存目录中的临时 zip，不要求用户选择本地保存位置。
- 上传远端备份必须有 HTTP 层防覆盖机制，不能因同秒命名碰撞覆盖旧备份。
- 上传失败不得影响本地保存与用户已有的本地备份文件。
- WebDAV 断网、鉴权失败或服务器异常不得阻塞本地自动保存。
- WebDAV 凭据不得写入 zip 包、日志、测试快照或错误提示。
- 下载 token 必须一次性 resolve，cleanup 后必须失效，显式清理应幂等且不得越界删除。
- 远端目录中的多个备份包不得被解释为需要自动合并的状态。
- 定时上传只能上传新快照，不得自动下载或恢复远端备份。

## 8. 测试计划

### 8.1 Rust 测试

- WebDAV URL 与远端目录规范化。
- WebDAV URL 默认拒绝 HTTP，允许 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP 开发例外。
- WebDAV base URL 拒绝 `userinfo`、`query` 与 `fragment`。
- WebDAV 远端目录只允许单级相对目录，拒绝 `..`、空段、反斜杠、URL 编码路径段、完整 URL、绝对路径和嵌套目录；空目录配置会规范化为 `SoNotes_Backups/`。
- WebDAV 配置加载、保存和清除命令能持久化非敏感字段、处理“不记住密码”，并删除对应密钥链 secret 或会话凭据。
- 鉴权失败映射为稳定错误。
- 网络不可达和超时映射为稳定错误。
- 上传时保留本地 zip 文件内容，不把本地文件名直接作为远端文件名。
- 上传远端备份使用 `If-None-Match: *` 或等价防覆盖机制；同名冲突时不会覆盖旧备份，并会等待下一秒后重新生成规范文件名或返回稳定冲突错误。
- 第一版不注册 `webdav_upload_backup(local_zip_path)`；若未来注册，Rust 会先校验 `local_zip_path` 是 SoNotes zip 备份，非备份 zip 或任意本地文件不会被上传。
- 创建远端备份时本地临时 zip 落在应用缓存目录，上传成功后清理，上传失败后进入过期或启动清理。
- 本地默认名 `sonotes-backup-${timestamp}.zip` 上传前会规范化为远端命名，并能被远端列表识别。
- 上传失败不删除或修改本地 zip 文件。
- 远端列表只返回符合严格正则 `^SoNotes_Backup_\d{14}\.zip$` 的 basename。
- `PROPFIND` XML 解析能处理 namespace、HTTP status、目录项排除、大小缺失与修改时间缺失。
- 下载远端备份前拒绝包含 `/`、`\`、`..`、URL 编码路径段或非规范扩展名的文件名参数。
- 下载远端备份时 `Content-Length` 超过 `MAX_WEBDAV_BACKUP_DOWNLOAD_BYTES`（建议 1 GiB）会被拒绝，缺少 `Content-Length` 时流式累计超限会中止下载并清理临时文件。
- 下载远端备份到安全临时路径并返回 download token，不返回裸本地路径。
- `resolve_downloaded_backup` 只为有效且尚未 resolve 的 token 返回受控本地路径，过期、重复 resolve 或目录不匹配时拒绝。
- `cleanup_downloaded_backup` 幂等；cleanup 后 token 失效，且不会删除 WebDAV 临时目录之外的路径。
- 下载失败、恢复失败、显式取消和过期清理都会清理临时文件。
- 下载后的 zip 仍由 `restore_local_backup` 负责校验与恢复。
- WebDAV 凭据不会出现在错误、日志、测试快照或返回给前端的错误对象中。

## 9. 验收标准

- 用户可以配置 WebDAV 地址、用户名、密码或应用令牌、远端目录。
- WebDAV 配置有加载、保存和清除接口；重启应用后配置恢复行为明确。
- 非本机 WebDAV 地址必须使用 HTTPS。
- WebDAV 地址不得包含 `userinfo`、`query` 或 `fragment`。
- WebDAV 远端目录拒绝目录跳转、空段、反斜杠、URL 编码路径段、完整 URL 和绝对路径，默认目录为 `SoNotes_Backups/`。
- WebDAV 远端目录第一版只允许单级目录，不支持嵌套目录或递归 `MKCOL`。
- 用户可以测试 WebDAV 连接并看到明确结果。
- 用户可以创建远端备份，流程会先在应用缓存目录生成临时 zip 快照再上传。
- 创建远端备份和定时上传前必须先刷新当前状态到磁盘；刷新失败时不得上传远端备份。
- 上传到远端的文件使用 `SoNotes_Backup_YYYYMMDDHHMMSS.zip` 命名。
- 当前本地默认名 `sonotes-backup-${timestamp}.zip` 上传后会被规范化为远端命名，并可被远端列表识别。
- 上传同秒触发或远端同名冲突时不得覆盖旧备份。
- 同名冲突重试仍使用 `SoNotes_Backup_YYYYMMDDHHMMSS.zip` 格式，等待下一秒后重新生成，不引入未纳入正则的后缀。
- 第一版不注册裸 `local_zip_path` 上传命令；如未来注册，必须先校验目标文件是 SoNotes zip 备份。
- 用户可以手动刷新远端备份列表。
- 远端列表只展示符合命名约定的 zip 备份包。
- 远端列表通过结构化 XML 解析 `PROPFIND` 响应，不依赖字符串拼接解析。
- 用户可以选择某个远端备份包下载并覆盖恢复。
- 下载远端备份有明确数值化最大下载字节数限制，建议 1 GiB；超限时本地数据不受影响且临时文件被清理。
- 下载流程对前端返回 download token；前端只能通过 token 获取受控本地路径后调用既有本地恢复流程。
- 同一个 download token 只能 resolve 一次；cleanup 后 token 必须失效。
- Rust 侧拒绝非规范远端文件名参数，不能通过路径段、目录跳转或 URL 编码绕过远端目录边界。
- 远端恢复必须复用本地 zip 恢复校验与恢复流程。
- 远端恢复的临时下载文件有 token 生命周期、显式清理和过期清理规则。
- 恢复前有二次确认，明确当前本地数据将被替换。
- WebDAV 断网、鉴权失败、上传失败、下载失败不会影响本地保存。
- 校验失败或恢复失败时当前本地数据不被破坏。
- WebDAV 凭据存储位置、“不记住密码”行为和脱敏规则明确，并有测试覆盖。
- 定时上传如实现，必须默认关闭，且只上传新快照。
- 所有用户可见文案只描述“远端备份 / 恢复”，不承诺实时同步、云同步或多端合并。
