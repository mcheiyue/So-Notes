**实现要点（写死）**

1. 重写 `useUIStore.setViewMode(mode)`（**唯一**完整逻辑）：
   - 读 `prev = state.viewMode`（uiStore 当前值；必要时与 useStore 桥后一致）。
   - **若 `mode === 'TRASH' && prev === 'BOARD'`**：取 runtime pan（优先 `useViewportStore.getState().viewport`，与 useStore.viewport 应已桥同步）→ `useStore.setState` 更新**当前** `boards` 中 `currentBoardId` 的 `viewport: { x, y }`（**不要** spread 进 history）。
   - `set` uiStore：`viewMode = mode`；`selectedIds = []`。
   - **若 `mode === 'TRASH'`**：`isDockVisible=false`；`contextMenu` 关默认；`smartPasteSplitPanel=null`；`isSpotlightOpen=false`；`isQuickCaptureOpen=false`；并对 viewportStore：`setStickyDrag(null)`（或等价重置对象）、`setPanMode(false)`。
   - **若 `mode === 'BOARD' && prev === 'TRASH'`**：读当前看板 `board.viewport`；若存在则 `useViewportStore.getState().setViewportPosition(x, y)`（桥写回 useStore）。
2. **禁止**新建 `src/services/*ViewMode*` / `src/utils/viewMode*`。
3. **禁止**在 appController 再复制一套副作用（入口已正确）。
4. 单测挂在 **生产路径**：优先扩展 `appController.test.ts`（调 `appController.setViewMode` / `toggleViewMode`），并可补 `uiStore.test.ts` 直接调权威；桥 `attachUISync` / `attachViewportSync` 在测中须已挂（与现网 beforeEach 一致）。
5. **真恢复 it 骨架**（必须）：

## 8. 收尾自检（无法自动证明 / 最可能返工）

1. **桥时序**：uiStore 写 UI 与 viewportStore 写 pan 的顺序若触发二次同步，是否出现「恢复后再被旧值盖住」→ 真恢复 it 必须在**挂桥**环境下跑。
2. **currentBoardId 缺失看板**：无 board 时保存 no-op；恢复 no-op——边界可不单测，但禁止 throw。
3. **同 mode 再设**：`setViewMode('TRASH')` 在已是 TRASH 时不应再次把 runtime 当 BOARD 保存（条件必须 `prev === 'BOARD'`）。
4. **isDockVisible 切回**：旧路径切 BOARD **不**自动 `isDockVisible=true`——本版保持；勿「顺手」打开 Dock。
5. **既有「恢复」测假绿**：useStore 旧测未改坏 pan 即过；Commit 2 后仍绿**不够**，真恢复 it 才关 C-V3。
6. **循环依赖**：uiStore 已 import useStore；再 import viewportStore 须确认无 TDZ/循环初始化；若有，用 `getState` 延迟取（与现网桥模式一致）。
7. **PowerShell 无 set -e**：前失败后仍跑 → 须逐条 throw。
8. **手测**：自动化不替代「真窗口 BOARD↔TRASH 平移保持」。
