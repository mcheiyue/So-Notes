# SoNotes v1.4.6 实施计划：撕下便签 Tauri 独立窗口

---

## 1. 背景

`v1.4.5` 已经完成撕下便签主窗口内浮层原型：用户可以从画布右键菜单将 **Note（便签）** 撕下为只读镜像浮层，并支持拖拽、定位到画布所在、置顶、贴回画布、内容同步、软删除自动关闭和监听器清理。

该原型验证了撕下便签的业务语义：撕下视图不是复制，也不是剪切，只是同一个 **Note** 的额外只读渲染视图。画布中的 **Note** 仍是唯一事实来源，撕下视图不修改 **Domain state（领域状态）**，也不进入 Undo/Redo 历史。

本版本将 `v1.4.5` 的主窗口内浮层推进为 Tauri 独立窗口版本。目标是让撕下视图成为真正的桌面窗口，支持 OS 级 always-on-top，并能在主窗口与撕下窗口之间稳定同步、定位和清理生命周期。

---

## 2. 目标

### 2.1 建立撕下便签独立窗口

- 为每个撕下的 **Note** 创建一个 Tauri 独立窗口。
- 窗口 label 使用 `detached-note-{noteId}` 格式，确保同一 **Note** 只对应一个撕下窗口。
- 撕下窗口渲染该 **Note** 的只读镜像，不提供标题或正文编辑入口。
- 撕下窗口不复用完整 `NoteCard`，继续复用 `NoteVisuals` 的纯展示能力。

### 2.2 从浮层置顶升级为 OS 级置顶

- `v1.4.5` 的“置顶”只表示主窗口内浮层 z-index 层级。
- `v1.4.6` 的“置顶”升级为 Tauri 窗口 `always-on-top`。
- 置顶只影响对应撕下窗口，不影响主窗口 Pin Mode。
- 取消置顶后，撕下窗口回到普通 OS 窗口层级。

### 2.3 定向同步 Note 快照

- 主窗口只向对应 `detached-note-{noteId}` 窗口发送当前 **Note** 的必要只读快照。
- 同步字段至少包括标题、正文、颜色、折叠状态和存在性。
- 同步必须定向发送到目标窗口，禁止全局广播全部便签状态。
- 便签被软删除或永久删除后，对应撕下窗口应自动关闭或进入可控关闭流程。

### 2.4 定位回主窗口

- 撕下窗口中的“定位到画布所在”应显示主窗口。
- 如果主窗口当前不在 **BOARD（看板）** 视图，应切回 **BOARD** 视图。
- 应切换到便签所属 **Board**，平移 **Viewport state（视口状态）** 使原便签居中，并高亮、选中原便签。
- 定位反馈是临时 **UI state（界面状态）**，不持久化。

### 2.5 保护多窗口焦点切换

- 从主窗口切到 SoNotes 自有撕下窗口时，主窗口不应被误判为离开应用而自动隐藏。
- 从撕下窗口切回主窗口时，主窗口应保持可预期的显隐、定位和高亮状态。
- 当前主窗口的失焦隐藏逻辑必须识别 SoNotes 自有窗口集合，而不是只检查 `main` 窗口是否失焦。

---

## 3. 非目标

本次不做以下能力：

- **第二份 Note 数据**：不为撕下窗口创建副本，不写入 `StorageData`。
- **直接编辑**：撕下窗口不提供标题、正文、颜色、折叠状态等编辑入口。
- **持久化撕下窗口状态**：不持久化撕下窗口的显隐、位置、大小、置顶状态；应用重启后清空。
- **全局事件广播**：不向所有窗口广播全部便签状态，只对目标撕下窗口发送对应 **Note** 快照。
- **Undo/Redo 接入**：打开、关闭、移动、置顶撕下窗口不进入 Undo/Redo 历史。
- **多端同步**：本版本不涉及 WebDAV、远端备份或同步语义。
- **撕下窗口参与画布交互**：撕下窗口不参与画布框选、多选、右键菜单、归拢、拆分、合并。
- **重启恢复撕下窗口**：不承诺应用重启后恢复上次撕下的窗口。
- **跨平台高级窗口特效**：不增加托盘拖放、悬停 Dropzone、系统级窗口吸附等高风险交互。

## 4. 业务边界决策

### 4.1 撕下窗口的语义

撕下窗口是 **Note** 的只读镜像视图，不是新的 **Note**。

- 画布中的 **Note** 是唯一事实来源。
- 撕下窗口只展示主窗口发送的当前 **Note** 快照。
- 用户在画布中修改 **Note** 后，撕下窗口同步展示最新内容。
- 用户关闭或贴回撕下窗口，不创建新 **Note**，不删除原 **Note**。
- 撕下窗口状态属于运行态 **UI state**，不进入持久化数据。

### 4.2 同一 Note 只允许一个撕下窗口

- 触发撕下操作时，如果 `detached-note-{noteId}` 已存在，应聚焦现有窗口。
- 如果窗口不存在，才创建新窗口。
- 主窗口需要维护 `noteId -> window label` 的运行态映射，或使用 Tauri window label 查询作为去重依据。

### 4.3 “置顶”的语义变化

`v1.4.6` 的“置顶”是 OS 级 always-on-top，不再是主窗口内 z-index。

- 置顶只影响目标撕下窗口。
- 置顶不修改主窗口 Pin Mode。
- 主窗口 Pin Mode 与撕下窗口 always-on-top 是两个独立概念。
- UI 文案应避免让用户误以为主窗口也被钉住。

### 4.4 “贴回画布”的语义

“贴回画布”只表示关闭当前撕下窗口，回到原始画布便签。

- 不复制便签。
- 不移动便签。
- 不修改便签所属 **Board**。
- 不改变 **Domain state**。

### 4.5 便签不存在时的处理

- 如果 **Note** 被软删除，对应撕下窗口应关闭。
- 如果 **Note** 被永久删除，对应撕下窗口应关闭。
- 如果撕下窗口请求定位时 **Note** 已不存在，主窗口可忽略定位请求。
- 如果便签所属 **Board** 已不存在，定位请求应安全失败，不抛出用户不可理解的错误。

## 5. 实施约束

### 5.1 当前代码是单主窗口模型

当前 Rust 侧窗口控制集中在 `src-tauri/src/lib.rs`，多处使用 `get_webview_window("main")`。`v1.4.6` 不能直接把这些逻辑照搬到撕下窗口，需要先区分主窗口与撕下窗口。

需要重点处理：

- 托盘显隐主窗口。
- 主窗口 Pin Mode。
- 主窗口失焦隐藏。
- 快速捕获、新建便签、剪贴板创建便签等只属于主窗口的事件。
- 撕下窗口自己的关闭、聚焦、置顶和生命周期。

### 5.2 主窗口失焦隐藏必须识别自有窗口集合

当前主窗口在 `Focused(false)` 后，如果未 pinned，会延迟检查并隐藏。独立撕下窗口引入后，点击撕下窗口会让 `main` 失焦，但这不应被视为离开 SoNotes。

规划要求：

- Rust 侧维护或识别 SoNotes 自有窗口集合。
- 主窗口失焦后必须通过异步短延迟稳定焦点状态，再检查焦点是否落在任一撕下窗口。
- 延迟检查建议控制在 50-100ms，避免 OS 焦点切换尚未完成时误判。
- 延迟必须用异步任务实现，不能阻塞 Tauri 事件处理。
- 鼠标离开触发的 `check_hide_on_leave` 也应考虑撕下窗口状态，避免主窗口在用户操作撕下窗口时被隐藏。

### 5.3 定向事件优先于全局事件

Tauri v2 支持按 window label 定向发送事件。撕下窗口同步必须使用定向事件。

生命周期清理不能依赖撕下窗口前端发出的“关闭通知”。前端页面可能在 React 卸载、`listen` 清理或事件发送前就被 OS 销毁；Rust 侧才是窗口生命周期的事实来源。

建议事件：

| 事件 | 方向 | 说明 |
|---|---|---|
| `detached-note:snapshot` | 主窗口 -> 撕下窗口 | 发送对应 **Note** 的只读快照 |
| `detached-note:missing` | 主窗口 -> 撕下窗口 | 通知对应 **Note** 已不存在 |
| `detached-note:locate` | 撕下窗口 -> 主窗口 | 请求定位到原便签 |
| `detached-note:close-requested` | 撕下窗口 -> Rust | 用户点击“贴回画布”时请求关闭当前撕下窗口 |
| `detached-note:closed` | Rust -> 主窗口 | Rust 监听到撕下窗口销毁后，通知主窗口清理运行态映射 |
| `detached-note:pin-changed` | 撕下窗口 -> 主窗口 | 同步该撕下窗口置顶状态 |

禁止用一个全局 `notes-updated` 事件把所有便签状态推给所有窗口。

### 5.4 权限配置必须前置检查

当前 `src-tauri/capabilities/default.json` 使用 `windows: ["*"]`，但权限列表中尚未包含创建 WebviewWindow 所需权限。

实施前需要确认并补充：

- `core:webview:allow-create-webview-window`
- 目标窗口所需的基础 window/webview 权限
- 如果从撕下窗口调用 Tauri API，应确认对应权限是否覆盖动态窗口 label

### 5.5 事件监听器必须清理

撕下窗口会注册关闭、聚焦、Note 快照监听和按钮事件。所有 `listen`、`onCloseRequested`、`onFocusChanged` 等监听器必须在窗口卸载或关闭时调用 `unlisten`。

规划要求：

- React 组件卸载时清理监听器。
- Rust 侧监听撕下窗口 `WindowEvent::Destroyed`，并以此作为清理 `noteId -> window label` 映射的最终依据。
- 撕下窗口前端只能发起关闭请求，不能作为生命周期清理的唯一来源。
- 主窗口退出时关闭所有撕下窗口或清理对应窗口句柄。

### 5.6 不让撕下窗口参与持久化刷写

当前持久化由主窗口运行时承担。撕下窗口只读，不应创建第二套保存订阅。

- 撕下窗口不初始化会写入 **Domain state** 的持久化服务。
- 撕下窗口不响应 `beforeunload` 触发的领域数据刷写。
- 撕下窗口关闭不应影响主窗口保存队列。

## 6. 技术设计

### 6.1 窗口创建方式

优先采用 Rust 侧统一创建撕下窗口，由主窗口通过 Tauri command 请求创建：

```ts
// 前端主窗口
await invoke('open_detached_note_window', { noteId });
```

Rust 侧负责：

- 检查 `detached-note-{noteId}` 是否已存在。
- 已存在则 show + set_focus。
- 不存在则创建 `WebviewWindow`。
- 设置初始窗口尺寸、透明度、装饰、可调整大小等窗口属性。
- 注册关闭和焦点事件。

优先放在 Rust 侧的原因：

- 现有窗口控制、托盘、Pin Mode、失焦隐藏都在 `lib.rs`。
- Rust 侧更容易维护 SoNotes 自有窗口集合。
- 可以减少前端直接创建窗口所需权限的扩散。

### 6.2 撕下窗口入口页面

撕下窗口需要一个独立入口，用于渲染只读镜像。

可选方案：

| 方案 | 说明 | 建议 |
|---|---|---|
| 独立 HTML | 为撕下窗口生成单独 HTML 入口，只加载只读镜像所需代码 | 优先 |
| 路由参数 | 使用同一前端 bundle，通过 URL query/hash 区分 `detached-note` 模式 | 仅作为不推荐备选 |

建议新增入口文件：

```text
detached.html
src/detached-main.tsx
src/components/DetachedNoteWindow.tsx
```

`detached.html` 只挂载撕下窗口根节点：

```html
<div id="detached-root"></div>
<script type="module" src="/src/detached-main.tsx"></script>
```

`vite.config.ts` 需要配置 Vite 多页入口，确保生产构建同时输出 `index.html` 与 `detached.html`。示意：

```ts
build: {
  rollupOptions: {
    input: {
      main: resolve(__dirname, 'index.html'),
      detached: resolve(__dirname, 'detached.html'),
    },
  },
}
```

Rust 创建撕下窗口时加载独立入口，例如：

```text
detached.html?noteId={noteId}
```

独立入口约束：

- 不导入 `App`。
- 不导入主窗口 `useStore`。
- 不挂载 `WindowShell`、画布、废纸篓、托盘事件、全局快捷键同步或持久化写入链路。
- 只监听 `detached-note:snapshot` 与 `detached-note:missing`，用组件本地 state 保存只读快照。
- 只通过 Tauri command 或定向事件发起定位、置顶、贴回画布等窗口操作请求。

### 6.3 撕下窗口组件

建议新增：

```text
src/components/DetachedNoteWindow.tsx
```

职责：

- 渲染 `NoteVisuals` 只读视图。
- 渲染定位、置顶、贴回画布控制按钮。
- 监听 `detached-note:snapshot` 更新本地只读快照。
- 监听 `detached-note:missing` 后关闭窗口或显示短暂关闭状态。
- 触发 `detached-note:locate`、`detached-note:close-requested`、置顶切换命令。
- 管理当前窗口的事件监听器清理。

### 6.4 主窗口控制器扩展

`appController` 保留撕下便签的业务入口，但需要从浮层状态迁移到窗口命令编排。

建议方法：

```ts
detachNote(noteId: string): Promise<void>
locateDetachedNote(noteId: string): Promise<void>
closeDetachedNote(noteId: string): Promise<void>
sendDetachedNoteSnapshot(noteId: string): Promise<void>
```

其中：

- `detachNote` 请求 Rust 创建或聚焦窗口。
- `locateDetachedNote` 复用 v1.4.5 的定位逻辑。
- `closeDetachedNote` 请求关闭对应窗口。
- `sendDetachedNoteSnapshot` 只向对应 label 发送最小快照。

### 6.5 UI state 调整

`v1.4.5` 的 `detachedNotes` 当前包含主窗口内浮层位置和 z-index 置顶状态。独立窗口版本需要重新定义运行态信息。

建议类型：

```ts
type DetachedNoteWindowState = {
  noteId: string;
  label: string;
  isAlwaysOnTop: boolean;
  lastSnapshotVersion: number;
};
```

不建议继续使用 `position: { x, y }` 作为核心字段，因为 OS 窗口位置由 Tauri window 管理，不属于主窗口内 CSS 坐标。

### 6.6 快照同步策略

主窗口维护对 `notesById[noteId]` 的精确监听或在领域变更后按已打开撕下窗口集合刷新对应快照。

快照发送必须做频率控制，不能在正文输入的每一次 `onChange` 后立即跨 Webview 发送 IPC。建议以 `noteId` 为粒度做 throttle 或 debounce，同一 **Note** 的快照同步间隔控制在约 100ms；主窗口内部 UI 可以即时渲染，跨窗口只读镜像允许轻微延迟。

快照结构：

```ts
type DetachedNoteSnapshot = {
  noteId: string;
  title: string;
  content: string;
  color: NoteColor;
  isCollapsed: boolean;
  deletedAt?: number | null;
};
```

同步规则：

- 只发送当前窗口对应 **Note**。
- 只发送只读渲染必要字段。
- 同一 **Note** 的连续变更应合并发送，避免 IPC 序列化和反序列化造成输入卡顿。
- **Note** 不存在或进入废纸篓时，发送 missing/close 指令。
- 不把整个 `notesById`、当前 **Board** 全量状态或 **Viewport state** 发送给撕下窗口。

### 6.7 关闭流程

关闭来源：

- 用户点击“贴回画布”。
- 用户点击窗口关闭按钮。
- 主窗口发现 **Note** 已进入废纸篓或被永久删除。
- 应用退出。

关闭要求：

- 用户点击“贴回画布”时，撕下窗口只向 Rust 发起关闭请求。
- Rust 负责关闭目标窗口，并在 `WindowEvent::Destroyed` 后通知主窗口清理映射。
- 主窗口清理 `detachedNotes` 运行态记录。
- 所有事件监听器调用 `unlisten`。
- 关闭撕下窗口不修改 **Domain state**。

## 9. 验收标准

### 9.1 独立窗口创建

- 在画布便签右键菜单点击“撕下便签”后，创建 `detached-note-{noteId}` 独立窗口。
- 同一 **Note** 再次触发撕下操作时，聚焦已有窗口，不创建重复窗口。
- 撕下窗口显示内容与原便签视觉保持一致。

### 9.2 只读边界

- 撕下窗口无法编辑标题或正文。
- 撕下窗口无法改变颜色、折叠状态或所属 **Board**。
- 撕下窗口打开、关闭、置顶不进入 Undo/Redo 历史。

### 9.3 内容同步

- 在主窗口画布修改便签标题后，撕下窗口同步展示最新标题。
- 修改正文、颜色、折叠状态后，撕下窗口同步展示最新内容。
- 同步只发送给对应撕下窗口，不影响其他窗口。
- 快速连续输入正文时，主窗口输入不应因快照 IPC 同步产生可感知卡顿。

### 9.4 三个按钮

- 点击“定位到画布所在”后，主窗口显示并切回对应 **Board**，视口定位到原便签并高亮。
- 点击“置顶”后，对应撕下窗口启用 OS 级 always-on-top；再次点击后取消。
- 点击“贴回画布”后，撕下窗口关闭，不创建副本，不删除原便签。

### 9.5 多窗口焦点

- 主窗口未 pinned 时，从主窗口点击撕下窗口，主窗口不会异常隐藏。
- 从撕下窗口点击回主窗口，主窗口状态可预期。
- 主窗口失焦到撕下窗口时，延迟焦点检查不会把短暂未完成的 OS 焦点切换误判为离开应用。
- 点击 SoNotes 外部窗口时，主窗口仍按既有规则自动隐藏。

### 9.6 生命周期清理

- 撕下窗口关闭后，主窗口运行态映射被清理。
- 通过 OS 关闭按钮关闭撕下窗口后，Rust 侧销毁事件仍能触发主窗口清理。
- 便签进入废纸篓后，对应撕下窗口自动关闭。
- 应用退出时，撕下窗口不会留下悬挂监听器或失效句柄。

- `npm run typecheck` 通过。
- `npm run test` 通过。
- `npm run build` 通过。
- `npm run tauri build -- --debug` 通过。
- 人工验证 Windows 环境下独立窗口创建、置顶、关闭、定位和焦点切换。

## 10. 风险

- 当前 Rust 侧窗口逻辑大量面向 `main` 窗口，迁移到多窗口时容易误把主窗口托盘行为套到撕下窗口。
- 主窗口失焦隐藏逻辑如果只看 `main` 是否 focused，会在点击撕下窗口时错误隐藏主窗口。
- OS 焦点切换不是原子过程，如果不做短延迟稳定检查，可能在撕下窗口尚未标记 focused 时提前隐藏主窗口。
- OS 级 always-on-top 会让撕下窗口浮在其他应用之上，语义比 `v1.4.5` 的 z-index 置顶更强，需要 UI 文案明确。
- Tauri capability 权限如果遗漏创建窗口或窗口操作权限，独立窗口会在运行时创建失败。
- 撕下窗口如果挂载完整主窗口应用，可能重复初始化持久化、快捷键、托盘事件或全局监听器；因此必须使用独立 HTML 入口。
- 定向事件如果实现成全局广播，会导致无关窗口收到不必要的 **Note** 数据，并增加调试难度。
- 快照同步如果不做节流，快速输入正文时可能造成 IPC 通信风暴和主窗口输入卡顿。
- 关闭事件如果没有清理 `unlisten`，多次打开关闭撕下窗口后可能出现监听器泄漏。
- 生命周期清理如果依赖撕下窗口前端主动通知，OS 关闭或 Webview 异常销毁后可能留下僵尸映射。
- 便签被软删除后如果窗口关闭，而用户随后撤销软删除，是否恢复撕下窗口仍需保持默认不恢复，避免把 **UI state** 纳入 Undo/Redo。

## 11. 已采纳的关键决策

### 11.1 独立窗口只读镜像

`v1.4.6` 的撕下窗口仍是只读镜像，不改变 **Domain state** 的事实来源。

### 11.2 使用 `detached-note-{noteId}` 作为窗口 label

窗口 label 与 **Note** 一一对应，用于去重、聚焦、定向事件和生命周期清理。

### 11.3 置顶升级为 OS 级 always-on-top

本版本的“置顶”不再是 CSS z-index，而是 Tauri 窗口置顶。该状态仍属于运行态 **UI state**，不持久化。

### 11.4 主窗口失焦隐藏必须识别 SoNotes 自有窗口

点击撕下窗口不等于离开应用，主窗口不能因此异常隐藏。

### 11.5 定向同步，不全局广播

主窗口只向对应撕下窗口发送该 **Note** 的只读快照，不广播全部便签状态。

### 11.6 撕下窗口不挂载持久化写入链路

撕下窗口只读，不初始化会修改或保存 **Domain state** 的持久化流程。

### 11.7 Rust 侧负责窗口生命周期真相

撕下窗口前端可以发起定位、置顶和关闭请求，但窗口是否已销毁、运行态映射何时清理，必须以 Rust 侧窗口事件为准。

### 11.8 撕下窗口使用独立 HTML 入口

撕下窗口不通过主应用路由分支启动，而是通过独立 HTML 入口加载极简只读运行时，避免重复初始化主窗口 store、持久化与全局监听器。
