## 1. 背景

`v1.5.1` 到 `v1.5.8` 已经把备份可信链、WebDAV 边界、凭据安全、定时远端备份、远端保留清理和活动日志逐步落地。总规划里 `v1.5.9` 的角色不是继续扩一个大功能，而是在进入 `v1.6.0` 前完成：

- 体验主题定稿。
- 关键流程冒烟基线。
- 低风险文案与反馈收口。
- `v1.6.0` 单主题计划书 / 原型说明。

过去几个 plan 的问题是“描述足够多，验证不够硬”，落地后容易靠后续 TDD 补洞。本计划按 `D:\OpenCode\方案.md` 的标准写成可验证方案：

- 横切约束单列，用矩阵呈现。
- 每条正确性约束都配可执行验证。
- 多接入点重复规则先建基础件，再强制复用。
- 每个 commit 写清范围、改动文件和验收命令 / 断言。
- 验证命令写成 shell 无关形式：纯字符串/JSON 断言收进 `node -e`/`node -p` 或 npm scripts，避免依赖 `test`/`grep`/`mkdir -p` 等在 PowerShell 下不稳的 POSIX 工具。工作区 shell 声明为 Git Bash，但实施者可能在 PowerShell 执行，故关键验收（版本一致、冒烟分段、禁用词分段）以 Node 脚本为准。仅当确认在 Git Bash 内执行时，才使用 `test`/`grep` 形式的等价命令。
- 末尾列出仍无法完全自动证明的项。

> **范围调整说明（本次审查后）**：原计划包含“程序触发 Viewport Action gate”（原 Commit 2/3、约束 C1-C4）。审查确认 `v1.5.9` 内没有该 gate 的真实消费者——现有 `locateAndSelectNote()` / `locateDetachedNote()` 由模态浮层或撕下窗口触发，不与画布 active drag / edge-push / sticky drag 并发；真正需要 gate 的“捕获后定位”“图片查看定位”都属于 `v1.6.0`。为避免为假设的未来需求预建抽象，gate 从 `v1.5.9` 移出，推迟到 `v1.6.0` 真正落地“捕获后定位”时再建（届时有真实消费者，defer 帧数也能按真实需求确定）。C1-C4 的约束意图转记入 `v1.6.0` 计划的 Viewport Action dependency。同步更新 `docs/plans/v1.5.1-to-v1.6.0-planning-recommendations.md` §12.2.3 / §12.4：预备阶段只做依赖评估与 defer 记录，不把“gate 已验证与三轨/拖拽不冲突”作为 `v1.5.9` 硬验收。

## 3. 版本目标

`v1.5.9` 完成时必须产出：

- `docs/qa/v1.5.9-smoke-baseline.md`：关键流程冒烟基线，至少一次执行记录。
- `docs/plans/v1.6.0-capture-and-organize-experience.md`：`v1.6.0` 单一主题计划书。
- `docs/prototypes/v1.6.0-capture-and-organize-flow.md`：轻量交互草图 / 流程说明。
- WebDAV / 备份文案“不暗示同步”的可执行断言。
- 版本号更新到 `1.5.9`。

推荐的 `v1.6.0` 主线预设为：

> 捕获与整理体验增强

**主题定稿**：以本文件为准。总规划 `docs/plans/v1.5.1-to-v1.6.0-planning-recommendations.md` §13.1 中“最终主题应由 v1.5.9 决定”的表述，在本 plan 定稿后**视为已闭合**；实施与验收不再要求重新选择主题。

原因：

- Quick Capture 当前已有入口，但目标看板提示、失败保留输入、捕获后定位 / 高亮仍是明显体验缺口。
- Spotlight 和 Image Note 在当前代码中已有较多可用能力与测试覆盖。
- 捕获增强符合总规划“捕获优先”的路线，也不触碰 WebDAV 同步误解。

`v1.6.0` 若实现“捕获后定位”，需先建程序触发 Viewport Action gate（本版本移出，见背景段范围调整说明）；该依赖须写入 `v1.6.0` 计划的 Viewport Action dependency，若 gate 风险不可控则 `v1.6.0` 降级为只做 Quick Capture 输入可靠性与目标看板反馈。

## 4. 非目标

`v1.5.9` 不做：

- 不实现标签系统。
- 不实现 WebDAV 同步、多端合并或冲突解决。
- 不开发多个 `v1.6.0` 候选主题。
- 不改变备份包格式。
- 不迁移主存储格式。
- 不重写 Canvas 渲染架构。
- 不让撕下便签进入可编辑模式。
- 不把快速捕获、搜索和图片查看三个方向同时做成运行时功能。

### C6：Image Note 冒烟必须覆盖粘贴、拖入、缺失占位、预览

约束：图片便签冒烟不能只写“图片正常”，必须拆成四项，与 `requiredById` 一一对应：

| `IMG-004` | 大图预览 | `预览` 或 `preview` |

### C7：Undo/Redo 只验证领域状态，不把 Viewport/UI 状态写入历史

约束：冒烟清单中的 Undo/Redo 项必须明确“领域状态变更进入历史，定位 / 预览 / 选区不进入历史”。

**关键**：必须包含 `useStore.test.ts`——它承载领域状态变更进入 Undo/Redo 历史的主实现契约。`undoRedoHistory.test.ts` 覆盖历史栈机制，`domainStore.test.ts` 覆盖领域状态变更，`appController.test.ts` 覆盖跨层集成。

**负向契约（文档 ↔ 测试不得脱节）**：冒烟文档写「定位/预览不进入 Undo」时，`useStore.test.ts` **必须**有对口负向具名测试，不得仅靠文档 `requiredById` 短语蒙混。

验证：`grep -nE` 无法区分命中行属于哪个 heading，故用脚本按 markdown heading 分段，只在非豁免段命中时判失败。注意：heading 文本本身也要查（`## 标签系统` 这类越界目标必须被拦），且豁免区按 heading depth 维护——一旦离开 `Non-goals`/`Deferred` 的子树（遇到同级或更高级 heading），豁免立即失效，避免豁免段后面的普通段被误放行。正则覆盖裸词和常见变体：

```bash
node -e '
const fs=require("fs");
const p="docs/plans/v1.6.0-capture-and-organize-experience.md";
const banned=/标签(?:系统)?|模板(?:系统)?|(?:云|双向|自动|WebDAV\s*)?同步|协作|SQLite|libSQL|数据库迁移|自动拉取|自动下载|自动恢复/;
const exemptTitle=/^#+\s*(Non-goals|Deferred)/i;
let exemptDepth=0, bad=[];   // exemptDepth>0 表示当前在豁免子树内
for(const line of fs.readFileSync(p,"utf8").split(/\r?\n/)){
  const h=line.match(/^(#{1,6})\s/);
  if(h){
    const depth=h[1].length;
    if(exemptDepth && depth<=exemptDepth) exemptDepth=0;      // 离开豁免子树
    if(exemptTitle.test(line)) exemptDepth=depth;             // 进入豁免子树
    if(banned.test(line) && !exemptDepth) bad.push(["<heading>",line.trim()]);  // heading 自身也查
    continue;
  }
  if(banned.test(line) && !exemptDepth) bad.push([line.trim()]);
}
if(bad.length){ console.error("banned term outside Non-goals/Deferred:", bad); process.exit(1); }
console.log("ok");
'
```
