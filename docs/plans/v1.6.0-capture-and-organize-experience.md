# SoNotes v1.6.0 计划书：捕获与整理体验增强

Primary Theme: 捕获与整理体验增强

> 本文件由 `v1.5.9` Commit 4 定稿。主题选择已在 `docs/plans/v1.5.9-prep-and-experience-baseline.md` 闭合，实施不再重新选型。

---

## Goals

- 强化快速捕获（Quick Capture）作为日常入口：目标看板可见、提交可靠、失败可恢复输入。
- 捕获成功后提供可理解的落点反馈：高亮新便签；在安全前提下可选程序定位到新便签。
- 保持领域模型与持久化格式不变：仍以看板 / 文本便签 / 图片便签 / 废纸篓为主。
- 与 `v1.5.8`–`v1.5.9` 备份可观测性兼容：不引入新的备份包格式，不改变活动日志语义边界。

---

## Non-goals

- 不做标签系统、模板系统。
- 不做多端合并、双向类能力、WebDAV 同步、云同步、自动同步、协作。
- 不做 SQLite / libSQL / 数据库迁移。
- 不做自动拉取、自动下载、自动恢复类产品能力。
- 不把 Spotlight 大改或图片查看大改作为本版本主线（见 Deferred）。
- 不让撕下便签进入可编辑模式。
- 不重写 Canvas 渲染架构。

---

## Current baseline

- `QuickCaptureOverlay`：已有浮层、剪贴板预填、IME Escape、统一视口落点创建文本便签；目标看板名展示与失败保留输入仍为体验缺口。
- `Spotlight`：已有搜索、跨看板定位；覆盖度较高，不作为本版本主交付。
- `ImageNoteBody`：已有加载、缺失占位、大图预览；不作为本版本主交付。
- `appController.locateAndSelectNote` / `locateDetachedNote`：由模态或撕下窗口触发；`v1.5.9` 未建通用 Viewport Action gate。
- 备份活动日志、WebDAV 远端备份、保留策略与断崖保护已在 `v1.5.7`–`v1.5.8` 落地；文案与冒烟基线在 `v1.5.9` 收口。

## Commit outline（建议）

1. **目标看板反馈**：Quick Capture 展示当前看板名（空名回退「当前看板」；过长截断）。
2. **捕获失败保留输入**：提交失败时保留草稿，不静默清空。
3. **捕获成功反馈**：新便签高亮；记录是否进入 Undo 的契约（仅领域创建入历史，视口/选区不入历史）。
4. **捕获后定位（可选）**：若落地，先建 Viewport Action gate，再接入 locate；风险不可控则砍掉定位，只保留 1–3。
5. **回归与发布**：冒烟扩展、CHANGELOG、版本号。

---

## Viewport Action dependency

- **背景**：`v1.5.9` 审查确认当时无 gate 真实消费者，已将程序触发 Viewport Action gate  defer 到本版本。
- **何时必须建 gate**：若实现「捕获成功后程序定位到新便签」，且可能与画布 active drag / edge-push / sticky drag / hover-panning 并发，则必须先建单一 gate 基础件，再接入 locate。
- **行为意图（验收方向）**：Idle/Regular 下定位语义与现网一致；God Mode 不误拦；active drag / edge-push / sticky drag 期间程序定位不得抢状态（延后或丢弃策略需在实现 commit 写死并测）。
- **降级**：若 gate 与三轨交互风险不可控，本版本降级为只做 Quick Capture 输入可靠性与目标看板反馈，**不做**捕获后程序定位。
- **非目标**：本 dependency 不要求在无「捕获后定位」消费者时预建抽象。

## Acceptance tests

- 目标看板：空名 / 长名 / emoji 名边界；文案使用「看板」语义，不使用「页面 / 工作区 / 项目」。
- 捕获失败：网络或 invoke 失败时输入保留；成功后清空。
- 捕获成功：新便签进入领域状态与 Undo；仅改视口/选区的反馈路径不写入 Undo。
- 若含定位：gate 单测 + 与拖拽并发的负向/延后用例；无 gate 不得宣称定位已完成。
- 回归：`QuickCaptureOverlay`、相关 store/controller 测试全绿；不破坏备份活动日志与 WebDAV 文案守卫。
