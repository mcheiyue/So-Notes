# SoNotes v1.5.5 旧 useStore 依赖地图

> 本地图是 v1.5.5 版本对旧 `useStore.ts` 全量依赖的执行索引，不是"引用计数减少"的指标表。目标是让后续版本能基于分类、风险和批次有序推进迁移，而不是重新考古。

---

## 1. 生产代码依赖地图

以下表格覆盖 `src/` 目录下所有以 `useStore`、`getState()`、`subscribe()` 形式依赖旧 `useStore` 的生产文件。`Domain` 写入不在 v1.5.5 迁移范围内，但必须记录在案，作为后续版本的执行入口。

审查时需区分旧 `useStore` 与已拆分的新 Store：`useSearchWorker.ts`、`useEdgePush.ts`、`useDarkMode.ts`、`Spotlight.tsx`、`PinFab.tsx`、`MiniMap.tsx` 虽然会被宽泛的 `getState()` / `use*Store` 搜索命中，但当前只依赖 `useDomainStore`、`useUIStore` 或 `useViewportStore`，不属于旧 `useStore` 剩余债务。

## 4. 剩余旧 useStore 风险摘要

引用数量减少不是本版本的唯一目标。以下才是 `v1.5.5` 需要持续关注的结构性风险：

### 4.1 跨层状态散落

旧 `useStore` 同时持有 Domain、Viewport、UI 三种状态，导致 `appController`、`Canvas`、`ContextMenu` 等模块在一个 Store 里混合读写不同层级。v1.5.5 通过依赖地图让这些散落可见，但不追求一次性清理。

### 4.2 React selector 性能边界

`Canvas`、`NoteCard`、`App` 等组件通过 `useStore(selector)` 细粒度订阅。迁移时如果粗暴替换为大对象订阅，可能破坏 MiniMap 的低频更新、NoteCard 的 memo 边界、Canvas 的按需重渲染。依赖地图中这些文件标记为 `medium` 或 `high`，不是因为功能风险，而是因为性能回归难以在测试中捕获。

### 4.3 备份恢复与持久化路径

`BoardDock` 的备份恢复、`PersistenceController` 的启动加载、`main.tsx` 的测试数据注入都直接操作旧 `useStore.setState()`。这些路径涉及数据完整性，不在 v1.5.5 触碰。

### 4.4 撕下窗口同步

`detachedNoteSnapshotSync` 通过 `useStore.subscribe()` 监听便签内容变化并同步到撕下窗口。这个订阅链跨越进程边界（Tauri webview），迁移时需要同时验证原生窗口行为。

### 4.5 Undo/Redo 历史栈

`ShortcutsManager` 的 undo/redo、`SelectionActionBar` 的批量操作、`NoteCard` 的编辑提交都依赖旧 `useStore` 的 `domainHistory`。`domainStore` 尚未接入完整历史栈，这些路径在 `domainStore` 完成历史栈迁移前不能动。

### 4.6 双向同步桥的维护成本

`uiStore` 和 `viewportStore` 的双向同步桥本身就是旧 `useStore` 的消费者。v1.5.5 保留这些桥，但每次新增迁移都必须验证桥不会产生循环同步。依赖地图中桥模块标记为 `blocked`，提醒后续版本在删除旧 `useStore` 前必须先迁移桥的依赖方向。

---

## 5. legacyDomainBridge 删除前提

`legacyDomainBridge` 将旧 `useStore` 的 Domain state 镜像到 `domainStore`。删除它需要同时满足以下四个条件：

1. **旧 useStore 不再作为 Domain 写入主路径。** 当前 `appController`、`CanvasEngine`、`Canvas`、`NoteCard`、`SelectionActionBar`、`TrashGrid`、`ShortcutsManager` 仍通过旧 `useStore.getState()` 或 `useStore.setState()` 执行 Domain 写入。这些写入必须先迁移到 `domainStore` action。

2. **Domain state 的订阅、持久化和测试不再依赖旧 store 镜像。** 当前 `diagnostics.ts` 订阅旧 `useStore` 获取便签统计；`PersistenceController` 读取旧 `useStore` 判断 `isLoaded`；大量测试通过 `useStore.setState()` 构造 Domain 夹具。这些消费者必须先迁移到 `domainStore` 或新测试夹具。

3. **Viewport / UI 迁移项已从旧 store 归位。** v1.5.5 已完成 `appController` 中 UI-only 和 Viewport-only 入口以及 `useCanvasGlobalListeners` 的 Spotlight 只读迁移到 uiStore / viewportStore。但 `uiStore` 和 `viewportStore` 的双向同步桥仍然需要旧 `useStore` 作为反向同步目标；Canvas、NoteCard、App、ContextMenu 等组件中的 Viewport / UI 读写仍在 later 批次。只有当所有 Viewport / UI 读写都已迁移到新 Store，且桥不再需要时，才能删除 `legacyDomainBridge`。

4. **Canvas、Undo/Redo、备份恢复、撕下窗口等关键交互已有迁移前后行为测试。** 这些路径在 `later` / `blocked` 批次中占大多数。删除 `legacyDomainBridge` 前，必须确认迁移不会破坏这些交互的用户可见行为。建议在每个关键路径迁移时同步补充行为测试。

满足条件 1 和 2 可以先解除 `legacyDomainBridge` 对 Domain 写入的依赖；满足条件 3 和 4 才能真正删除桥代码。预计最快在 `v1.5.7` 或 `v1.5.8` 后评估。
