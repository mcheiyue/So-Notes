### 5.1 C27 — Batch Undo（基础件，Commit 1）

> **语义锁定（方案 A，禁止含糊）**：batch 成功后 **只 push 1 条** history entry；**一次** `undoDomainChange()` 整批撤销；**一次** `redoDomainChange()` 整批恢复。  
> 单条 `addNoteWithContent` 仍为 **非 compound** 的 `remove-note`/`add-note`；batch **刻意**用 compound 包 N 条，与单条形状不同但栈语义一致（一 entry = 一用户手势）。

**实现要点（写死）**

- 仅改 `useStore.addNotesWithContentBatch`；**本 commit 禁止改 Overlay / 版本号 / UI / Canvas / appController 源码**。
- **影响面（必读）**：补 history 后，**全部** store 级调用方共享 Undo 语义：`QuickCaptureOverlay`、`Canvas` 智能粘贴、`appController.smartPasteFromText`。验收以 store 四条 `store 历史:` it 为准；**不**要求为每个调用方各写一套 history it，但 **必须**跑 §5.1「调用方回归」块（既有 it / 文件组 `numFailedTests===0`），防止 compound 栈破坏单条 undo。
- 成功写入 notes **之后**（与 selection/highlight 同一 `set` 内或紧随其后）调用 `pushHistoryEntry`：
  - `label`：**固定** `'add-notes-with-content-batch'`（与单条 `'add-note-with-content'` 区分）
  - **undo**：`{ type: 'compound-patch', patches: createdIds.map(id => ({ type: 'remove-note', noteId: id })) }`
  - **redo**：`{ type: 'compound-patch', patches: createdNotes.map(note => ({ type: 'add-note', note: { ...note } })) }`（**创建时**拷贝完整 Note 快照，含 id/x/y/z/color/content/boardId/kind/title/collapsed/createdAt/updatedAt）
- `normalizedNotes.length === 0`：**不** `pushHistoryEntry`，返回 `[]`；`domainHistory.undoStack.length` 不变
- 本 API **无** `recordHistory` 参数：始终 push（与当前无 options 签名一致）
- 不引入新 DomainPatch 类型
- **禁止**改 `HistoryStack` 字段名；读写只用 `domainHistory.undoStack` / `domainHistory.redoStack`
- **禁止**调用不存在的 `undo()` / `undoDomain`；测试与文档一律 `undoDomainChange` / `redoDomainChange`
- **禁止**为「只给 QC undo」另开 API 或 `recordHistory: false` 旁路

### 5.4 C24 — 失败保留输入（Commit 4）

**实现要点**

- `submit` 包 `try/catch`（若将来 batch 改 async，改为 `await` 后仍走同一 catch）。
- **失败**：保留 `value`、保持 `isQuickCaptureOpen === true`、展示可感知错误（见下方 **错误 UI 钉死**）。
- **成功**：`setValue('')`、清除错误节点、关闭浮层。
- 当前 `addNotesWithContentBatch` 几乎不 throw：实现仍写 catch；测试用 **可注入失败**。
- **与主题书失败语义对齐（写死，禁止实施时另猜）**：主题书 Acceptance 写「submit 路径抛错时输入保留」。现网 batch **非 async、仅本地 store、不经 invoke/网络**；本版 **不**引入真实网络/Tauri invoke 失败路径。自动化与 DoD 的失败构造 **= §5.4 render 前 mock/setState 注入 throw**（**首选** `setState` 替换 batch；次选 render 前 `vi.spyOn`），语义上覆盖「submit 路径任意 throw → 保留输入」；**禁止**为凑旧「网络/invoke」字面去 mock `invoke` / 假网络层。生产日后若 batch 变 async/invoke，仍走同一 try/catch，不另开失败通道。

**现网保持 · 本版不验收（非正确性约束、非 DoD、非冒烟 REQUIRED）**

| 行为 | 现网约定（描述性，非本版验收项） | 本版纪律 |
| --- | --- | --- |
| **空提交**（textarea 空 / 解析后 `notes.length === 0`） | early return：**不清空、不关、不报** `role=alert` | **保持现网**；**不**写入 C24 正确性构造表；**不**强制新建 `失败保留:` / `文案守卫:` 负向 it；顺手加测 **不得**改 DoD / 冒烟 `REQUIRED_IDS` |
| **取消 / Escape / 点遮罩关闭** | 关闭浮层；现网 `isOpen→false` 时 effect 可 `setValue('')`；关闭时宜清错误态 | **保持现网取消语义**；**不**与「失败保留草稿 + alert」混为同一正确性条；**不**新增本版 DoD it |

> 上表 **不是** C24 验收输入→输出。C24 **仅**验收：注入 throw → 保留+open+alert；注入成功 → 清空+关闭+无 alert（见下构造与精确 it）。

**失败注入构造（写死；禁止「或」「实施时再定」）**

> **Zustand selector 闭包（硬，禁止 render 后再 spy）**  
> Overlay 通过 `useStore((s) => s.addNotesWithContentBatch)` **在 render 时**取函数引用。  
> **禁止**在组件已 mount / 已打开浮层之后再 `vi.spyOn(useStore.getState(), 'addNotesWithContentBatch')` 指望命中——该 spy **可能改不到**已闭包引用 → 组件仍调生产实现、mock 0 次、it 假红或假绿。  
> **必须**在**首轮 render 与打开浮层之前**完成 mock 绑定，且提交时组件调用的是 mock（硬门槛：调用 ≥1 次）。

| 步骤 | 做法 |
| --- | --- |
| 0 | `beforeEach`/`afterEach` 必须 `mockRestore` / 还原 store 方法，防止污染后续 it |
| 1 | **首选（推荐）**：在 **render / 打开浮层之前** `const mockBatch = vi.fn(() => { throw new Error('inject-fail') })`；`const orig = useStore.getState().addNotesWithContentBatch`；`useStore.setState({ addNotesWithContentBatch: mockBatch })`。组件随后 render 时 selector 直接拿到 mock |
| 1b | **次选**：仅当 setState 替换在本仓库测试基建下不可用时，在 **render 前** `const spy = vi.spyOn(useStore.getState(), 'addNotesWithContentBatch').mockImplementation(() => { throw new Error('inject-fail') })`，**然后**再 render / 打开浮层。若 spy 后组件调用次数仍为 0 → **必须**改回步骤 1，**禁止**为绿改业务代码或去掉「调用≥1」门槛 |
| 2 | 打开浮层（`setQuickCaptureOpen(true)` 或等价），textarea 设为固定串 **`保留草稿-注入失败`** |
| 3 | 点击「创建」按钮（或 submit 表单） |
| 4 | **硬门槛**：mock/spy **被调用 ≥1 次**（`expect(mockBatch).toHaveBeenCalled()` / `expect(spy).toHaveBeenCalled()`；证明组件走到了注入路径，非「生产路径自然 throw」假绿） |
| 5 | 断言：textarea **value 仍为** `保留草稿-注入失败`；`useUIStore.getState().isQuickCaptureOpen === true`；`getByRole('alert')` 文本含 **`创建失败，输入已保留`** |
| 6 | `setState` 还原 `orig`，或 `spy.mockRestore()`；`afterEach` 统一还原 |

成功路径（同 it 文件另一条；**仅服务「关闭/清空/无 alert」断言**）：

| 步骤 | 做法 |
| --- | --- |
| 1 | **首选（推荐）**：render **前** `const mockBatch = vi.fn(() => ['id-injected-ok'])`；`useStore.setState({ addNotesWithContentBatch: mockBatch })`（返回非空 id；**不** throw；**不**要求真实写入 `notesById`） |
| 1b | **次选**：render **前** `vi.spyOn(useStore.getState(), 'addNotesWithContentBatch').mockReturnValue(['id-injected-ok'])`，再 render；若调用 0 次 → 改回步骤 1 |
| 2 | 打开浮层，输入非空内容，点「创建」 |
| 3 | **硬门槛**：mock/spy **被调用 ≥1 次** |
| 4 | 断言：textarea value 为 `''`；`isQuickCaptureOpen === false`；`queryByRole('alert')` 为 null |
| 5 | 还原 `addNotesWithContentBatch` / `mockRestore` |

> **mock 边界（硬）**：上表成功 mock **只**证明失败保留的对称路径（清空+关闭）。**禁止**用 `['id-injected-ok']` 假 id 去验收 C25 高亮、C27 history、或 **C29 定位**（定位会读 `notesById` / 坐标 / `locateAndSelectNote`）。若实施或验收 Optional C29，成功路径须改用 **真实** `addNotesWithContentBatch`（或完整 stub：写入 notesById + 合法 x/y/boardId + 返回真实 id），并在 C29 it 内 spy `locateAndSelectNote`。C24 两条 it **不得**依赖 locate。

> **注入纪律（硬）**：**首选 render 前 `setState` 注入 mock**；`vi.spyOn` 仅次选且**必须**在 render 前。禁止 render 后再 spy；禁止依赖「生产路径自然 throw」；禁止只 mock 模块 export 却不断言组件仍绑定到 mock。**每条 C24 it 内 mock/spy 被调用 ≥1 次** 为硬门槛；未达则 it 失败，不得靠 UI 表象假绿，不得为绿删门槛或改业务。

**失败 vs 取消（仅澄清；取消见上「现网保持 · 本版不验收」）**

- **失败**（C24 DoD）：保留草稿 + 显示 `role="alert"` + 浮层不关。
- **取消 / Escape / 遮罩**：见上表；**不**进本版 C24 验收。

### 5.6 C29 — Optional：捕获后定位 + 最小 gate

**仅当明确做 Optional 时实施。**

**实现要点**

```ts
// 真源：useViewportStore.getState()（与 useStore 镜像字段同源；以 viewportStore 为准）
// stickyDrag 与 interaction 并列，禁止写成 interaction.stickyDrag
type EdgePush = { top: boolean; bottom: boolean; left: boolean; right: boolean }
type StickyDrag = { id: string | null; offsetX: number; offsetY: number; status: 'active' | 'suspended' }

function isEdgePushOccupied(edgePush: EdgePush): boolean {
  return edgePush.top || edgePush.bottom || edgePush.left || edgePush.right
}

function isStickyDragOccupied(stickyDrag: StickyDrag): boolean {
  return stickyDrag.id != null // status 不单独作占用判据
}

function canRunViewportAction(
  interaction: { isDragging: boolean; isPanMode: boolean; edgePush: EdgePush },
  stickyDrag: StickyDrag,
): boolean {
  // 占用 → false：isDragging / isPanMode / edgePush 任一侧 true / stickyDrag.id != null
  // Idle/Regular（全部占用 false）→ true
  // 不引入全局事件总线、不抽象 Framework、不新增 godMode 状态字段
  // 禁止读取 edgePush.active（现网无此字段）
  if (interaction.isDragging || interaction.isPanMode) return false
  if (isEdgePushOccupied(interaction.edgePush)) return false
  if (isStickyDragOccupied(stickyDrag)) return false
  return true
}
```

**占用策略（写死，覆盖主题书「延后或丢弃」二选一；覆盖总规划 §12.2.3「应延后到拖拽结束」）**

> **策略 = 丢弃本次 locate，非延后。**（总规划「如必须定位，应延后到拖拽结束」**不**作为本版实现；见文首冲突仲裁。）

> - 用户仍保留 batch 成功结果：`selectedIds` + `created` 高亮 + 浮层关闭。  
> - **禁止** invent「占用结束后自动补定位」；若产品日后要延后策略，**另开版本**，不得在 v1.6.0 静默改语义。
