# SoNotes v1.4.2 实施计划：托盘状态提示与快速捕获层修复

---

## 1. 背景

SoNotes 当前已经具备托盘常驻、快速捕获、保存状态反馈与窗口圆角壳层。`Ctrl+Alt+N` 快速捕获入口已存在，但实际视觉上存在一个圆角对齐问题：快速捕获遮罩渲染在 `WindowShell` 之外，导致它没有和窗口圆角裁剪域保持一致。

本次 `v1.4.2` 不扩展新的产品能力，只做两个小而明确的修复与增强：

1. 修复快速捕获层的圆角对齐问题。
2. 让托盘 tooltip 能展示当前看板与保存状态。

---

## 2. 目标

### 2.1 快速捕获层圆角对齐

- 将 `QuickCaptureOverlay` 纳入 `WindowShell` 的裁剪域。
- 让快速捕获遮罩、对话框和窗口圆角保持一致。
- 保证 `Ctrl+Alt+N`、托盘菜单“快速捕获”和现有快速捕获测试继续成立。

### 2.2 托盘 tooltip 状态提示

- 托盘 tooltip 可显示当前看板名。
- 托盘 tooltip 可显示保存状态。
- 保存失败时，tooltip 至少能反映异常状态，方便用户快速感知。

### 2.3 测试补强

- 增加对快速捕获层布局归属的测试。
- 增加对 tooltip 文案与状态同步的测试。
- 保持现有托盘事件、快速捕获打开链路、保存状态反馈测试通过。

---

## 3. 非目标

本次不做以下能力：

- 托盘双击语义。
- 托盘中键操作。
- 托盘拖放。
- 悬停托盘 Dropzone。
- 剪贴板栈。
- 多窗口撕下便签。
- 附件 / 图片存储模型。
- WebDAV 远端备份。

---

## 4. 提交拆分建议

### Commit 1：规划文档

- 新增本文件，明确 `v1.4.2` 的目标、非目标和验收标准。

### Commit 2：快速捕获层修复

- 修改 `QuickCaptureOverlay` 的挂载位置与定位方式。

- 补充测试，验证快速捕获层位于 `WindowShell` 内。

### Commit 3：托盘 tooltip

- 补充测试，验证状态变化时 tooltip 文案能同步更新。

---

## 5. 详细实现约束

### 5.1 快速捕获层

- 快速捕获层必须和 `WindowShell` 的圆角裁剪域保持一致。
- 快速捕获层根节点不应再使用全视口 `fixed inset-0` 直接覆盖矩形 WebView。
- 若继续使用遮罩，必须让它成为壳层的一部分。
- 快速捕获层不能影响 `Spotlight`、`BoardDock`、`MiniMap` 的既有层级。

### 5.2 托盘 tooltip

- tooltip 更新应尽量复用现有保存状态与看板状态，不额外引入复杂状态机。
- Linux 平台可以降级，不应阻塞主流程。
- tooltip 只作为信息提示，不替代菜单入口。

### 5.3 测试

- App 级测试要覆盖 shell 内外层级契约。
- 快速捕获测试要覆盖打开后可见性与输入事件。
- tooltip 测试要覆盖前端状态到 Rust 调用的链路。

---

## 6. 验收标准

- `Ctrl+Alt+N` 打开的快速捕获层与窗口圆角对齐。
- 快速捕获遮罩不再外溢到窗口圆角外侧。
- 托盘 tooltip 能展示当前看板名与保存状态。
- 保存状态变化时，tooltip 能同步更新或至少在下次状态变更时更新。
- 现有相关测试全部通过。

---

## 7. 风险

- `WindowShell` 与壳外浮层的层级调整可能影响其它 overlay 的视觉层次。
- Rust 托盘句柄的持有方式需要与 Tauri v2 API 对齐。
- 状态同步时如果过于频繁，tooltip 更新可能带来不必要的噪音。

---

## 8. 一句话总结

`v1.4.2` 只做两件事：把快速捕获层收回窗口圆角里，并让托盘 tooltip 说清楚当前看板和保存状态。
