# v1.4.1 菜单与操作入口整合

---

## 1. 背景

v1.4.0 完成了 store 拆分与跨层编排收口，`appController` 已接管大部分交互入口。但在整合过程中，菜单与操作入口暴露了若干一致性问题：

- 右键菜单（`ContextMenu`）的颜色选项使用硬编码的 6 色列表（Yellow/Green/Blue/Red/Purple/Gray），与 `NoteCard` 的 13 色循环和 `SelectionActionBar` 引用的 `NOTE_COLORS.slice(0, 6)` 三处颜色源互不统一。
- 右键菜单的颜色以扁平行内色块展示，占据菜单纵向空间，与其他菜单项的交互模式不一致。
- 多选操作栏（`SelectionActionBar`）的颜色以永久色块行嵌入工具栏，占用主操作空间，且与右键菜单和快捷改色入口的色板策略不一致。
- 右键菜单大量使用 emoji 图标（📑📝📋🧹🧲🧩📦⬆️⬇️✂️📄➡️⤴️🔝📤🗑️）和英文开发者注释（"(Arrange)"、"(Smart Arrange)"、"(Click Again)"），与项目已建立的 lucide-react 图标体系不协调。
- 确认文案在右键菜单、多选操作栏、废纸篓之间不统一（例如"确认归拢?" vs "确认永久删除选中的 N 个便签吗?"）。

本次版本聚焦菜单与操作入口的视觉统一、颜色配置收敛和文案规范化，不涉及 Domain 逻辑变更。

---

## 2. 目标

1. 统一所有主动改色入口的 UI 色板：从现有 `NOTE_COLORS`（`src/store/types.ts`，13 色）中收敛出 6 色 `UI_PALETTE`，并共享同一套展示配置。
2. 右键菜单颜色改为子菜单（secondary menu）模式，鼠标悬停"颜色"菜单项时展开色板。
3. 多选操作栏颜色改为紧凑气泡/弹出触发器（compact popover trigger），点击后展开 6 色 UI 色板，不再以永久色块行占用工具栏空间。
4. `NoteCard` 的快捷改色入口改为在同一套 6 色 UI 色板中循环。
5. 右键菜单全部 emoji 替换为 lucide-react 图标，英文注释替换为中文。
6. 归拢/删除/永久删除等确认文案统一风格。
7. 所有 UI 入口调用 `appController` 方法，不引入 Domain 逻辑变更。

---

## 3. 非目标

- 不删除 `NOTE_COLORS` 中已有 13 色；历史便签使用的旧色值必须继续可渲染。
- 不做颜色数据迁移，不批量改写既有便签颜色。
- 不修改 `appController` 的 Domain 方法签名或业务逻辑。
- 不修改 store 类型定义（`types.ts`）。
- 不引入新的依赖包。
- 不涉及标签（tag）功能（原 v1.4.1 标签筛选计划已移至 v1.4.5+）。

---

## 4. 实施约束

- 所有菜单操作必须通过 `appController` 公开方法，禁止在组件内直接调用 `useStore.getState()` 进行 Domain 写入（沿用 v1.4.0 §0.5 约束）。
- 状态边界保持不变：便签颜色本身仍属于 Domain state；`UI_PALETTE` 只是新增/改色入口的展示约束，颜色子菜单、气泡显隐与悬停目标属于短暂交互态，不进入 Domain state。
- 子菜单/弹出层的显隐状态优先使用 React 本地 `useState`，不写入全局 store。
- 禁止 `as any`、`@ts-ignore`。
- 每个提交必须通过 `npm run typecheck`、`npm run test`、`npm run build`。

## 6. 代码级工作流

### 工作流 1：定义 6 色 UI 色板并统一颜色入口

**目标**：保留 `NOTE_COLORS` 13 色作为兼容渲染色板，同时为所有主动改色入口定义一套 6 色 `UI_PALETTE`。

**UI_PALETTE 候选色**：

| 语义 | 色值 | 来源 |
|---|---|---|
| 纯白 | `#FFFFFF` | `NOTE_COLORS` |
| 明黄 | `#fef9c3` | `NOTE_COLORS` |
| 淡绿 | `#dcfce7` | `NOTE_COLORS` |
| 浅蓝 | `#dbeafe` | `NOTE_COLORS` |
| 浅红 | `#fee2e2` | `NOTE_COLORS` |
| 淡紫 | `#f3e8ff` | `NOTE_COLORS` |

**步骤**：

1. **store/types.ts 或相邻颜色配置模块**：保留 `NOTE_COLORS` 13 色不变，新增 `UI_PALETTE` / `NOTE_UI_COLORS` 之类的 6 色导出。
2. **ContextMenu.tsx**：删除组件内硬编码的 `colors` 数组，改为引用统一 UI 色板配置。
3. **SelectionActionBar.tsx**：移除 `NOTE_COLORS.slice(0, 6)` 的局部截断逻辑，改为引用同一份 UI 色板配置。
4. **NoteCard.tsx**：`cycleColor` 不再遍历完整 `NOTE_COLORS`，改为遍历同一份 UI 色板；若当前便签颜色不在 UI 色板内，下一次点击从 UI 色板第一个颜色开始。
5. 如需颜色名称、排序或可访问文案，放在统一配置里，避免在三个组件内重复维护。

**验收**：右键菜单、多选操作栏、`NoteCard` 快捷改色均使用同一套 6 色 UI 色板；旧便签使用 13 色中的非 UI 色值时仍可正常显示。

### 工作流 2：右键菜单颜色改为子菜单

**目标**：颜色选项从扁平行内色块改为悬停展开的子菜单。

**步骤**：

1. 在 `ContextMenu.tsx` 中，将 L293-314 的颜色色块区域替换为一个带 `ChevronRight` 的菜单项"颜色"。
2. 复用已有的子菜单机制（`activeSubmenu` + `handleSubmenuEnter/handleSubmenuLeave` + 300ms 延迟关闭），新增 `'COLOR'` 子菜单类型。
3. 子菜单内渲染 `NOTE_COLORS.map(color => ...)` 色块按钮，每个按钮点击后调用 `appController.changeNoteColor` 或 `appController.changeSelectedNotesColor`。
4. 子菜单定位逻辑复用已有的 `submenuOffsetClass` 与 `submenuMaxHeight`。
5. 在 `activeSubmenu` 类型中扩展 `'MOVE' | 'COPY' | 'COLOR'`。

**验收**：鼠标悬停"颜色"菜单项时展开 6 色 UI 色板子菜单；移出后 300ms 自动收起；点击色块后菜单关闭并改色。

### 工作流 3：多选操作栏颜色改为紧凑弹出触发器

**目标**：颜色从永久色块行改为点击触发的紧凑 popover。

**步骤**：

1. 在 `SelectionActionBar.tsx` 中，将 L61-72 的色块行替换为一个紧凑的"改色"按钮（使用 lucide-react `Palette` 图标 + "改色" 文字）。
2. 点击该按钮后，弹出一个绝对定位的色板面板（`Popover`），渲染 6 色 UI 色板按钮。
3. Popover 使用 React `useState` 控制显隐，不写入全局 store。
4. Popover 定位在按钮上方或下方（根据视口空间自动翻转）。
5. 点击色块后关闭 popover 并调用 `changeSelectedNotesColor`。
6. 点击 popover 外部关闭（`useEffect` + `mousedown` 监听）。

**验收**：工具栏默认不显示色块，点击"改色"按钮弹出 6 色面板；选择颜色后面板关闭；工具栏视觉更紧凑。

### 工作流 4：右键菜单 emoji 替换为 lucide-react 图标

**目标**：全部 emoji 替换为 lucide-react 图标，英文注释替换为中文。

**图标映射表**：

**验收**：菜单中无 emoji、无英文开发者注释；图标与 `BoardDock`、`Spotlight` 等已有 lucide 体系一致。

### 工作流 5：确认文案统一

**目标**：归拢、软删除、永久删除等确认文案风格统一。

**统一规则**：

- 破坏性操作（软删除、永久删除）：红色高亮 + 明确动作后果，例如“确认软删除？”或“确认永久删除？此操作无法撤销。”
- 可逆操作（归拢）：正常色 + “确认归拢？”（不附加 “(Click Again)”）
- 批量操作：统一使用“确认{动作}选中的 {N} 个便签？”格式
- 废纸篓场景：沿用 `window.confirm`，但统一措辞风格

**步骤**：

1. **ContextMenu.tsx**：将 `"整理选中 (Arrange)"` 改为 `"整理选中"`；将 `"一键归拢 (Smart Arrange)"` 改为 `"一键归拢"`；将 `"确认归拢? (Click Again)"` 改为 `"确认归拢？"`。
2. **ContextMenu.tsx**：将 `"确认删除 N 个便签?"` 改为 `"确认软删除选中的 {N} 个便签？"`。
3. **TrashGrid.tsx**：将 `"确认永久删除选中的 N 个便签吗? 此操作无法撤销。"` 改为 `"确认永久删除选中的 {N} 个便签？此操作无法撤销。"`。
4. **TrashGrid.tsx**：将 `"确认还原所有便签吗?"` 改为 `"确认还原所有便签？"`。
5. **TrashGrid.tsx**：将 `"确认清空废纸篓吗? 此操作无法撤销。"` 改为 `"确认清空废纸篓？此操作无法撤销。"`。

**验收**：所有确认文案使用中文标点；软删除与永久删除区分清楚；批量操作文案格式一致。

## 8. 验收标准

1. 右键菜单无 emoji，全部使用 lucide-react 图标。
2. 右键菜单无英文开发者注释（Arrange、Smart Arrange、Click Again）。
3. 右键菜单颜色以子菜单形式展示，包含统一 6 色 UI 色板。
4. 多选操作栏颜色通过"改色"按钮触发 popover，包含统一 6 色 UI 色板。
5. 多选操作栏默认不显示色块行，视觉更紧凑。
6. `NoteCard` 点击 Palette 按钮以统一 6 色 UI 色板循环改色；旧的非 UI 色值仍可正常渲染。
7. 所有确认文案使用中文标点，且软删除与永久删除的后果表达清楚。
8. `npm run typecheck`、`npm run test`、`npm run build` 全部通过。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 子菜单在窄屏/边缘时溢出 | 复用已有的 `shouldFlipSubmenuLeft` + `submenuMaxHeight` 逻辑 |
| Popover 在多选操作栏底部时翻转不当 | 计算视口空间，动态决定向上或向下弹出 |
| emoji 替换后测试大量文本断言失败 | 优先修复断言，不改变测试覆盖范围 |
| 确认文案统一影响用户习惯 | 变化幅度小，主要是移除英文注释、统一中文标点并补清动作后果 |

---

## 10. 回滚方案

- 每个工作流可独立回滚：git revert 对应提交即可。
- 颜色子菜单回退为扁平行内色块：仅需还原 ContextMenu 中的颜色渲染区域。
- Popover 回退为永久色块行：仅需还原 SelectionActionBar 中的颜色渲染区域。
- emoji 回退：还原 `<span>` 标签即可。
- 确认文案回退：还原字符串字面量即可。

---

## 11. 提交计划

建议按工作流拆分为 3-5 个提交：

1. **颜色数据源统一 + 子菜单 + popover**（工作流 1-3）
2. **emoji 替换为 lucide-react 图标**（工作流 4）
3. **确认文案统一**（工作流 5）
4. **测试适配**（工作流 6）

每个提交独立可回滚，独立通过 typecheck/test/build。
